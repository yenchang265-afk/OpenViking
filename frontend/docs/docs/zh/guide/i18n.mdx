# 國際化

業務元件和區塊內建簡體中文和英文兩套文案，通過 `locale` 切換，不依賴 i18next 等翻譯庫。

## 設定語言

`locale` 的取值是 `'zh-CN' | 'en-US'`，按下面的順序取第一個有值的：

1. 元件自己的 `locale`
2. 元件所在區塊的 `locale`
3. 最近的 `OpenVikingProvider` 的 `locale`，巢狀的 Provider 省略時繼承外層
4. 預設值 `'en-US'`

在應用根部的 `OpenVikingProvider` 上設定一次，其餘業務元件和區塊都可以省略 `locale`。區塊的語言同時作用於區塊內建檢視和你傳入的插槽。

## 覆蓋文案

每個業務元件和區塊的 `labels` 用來修改單條文案：

- 傳入的欄位優先於當前語言的預設文案。
- 省略或為 `undefined` 的欄位使用當前語言的預設文案，切換語言後隨之更新。
- 空字串保留為顯式覆蓋，對應文案顯示為空。
- 巢狀物件逐鍵合併，覆蓋一個欄位不會丟掉其他預設項。

業務內容、插槽和回呼裡的文案由你提供，不隨 `locale` 翻譯。

## 切換語言

切換語言只更新介面文案，不會重新發起請求，也不會清空記錄、會話或輸入草稿。服務端返回的內容、錯誤原文、AI 回覆和使用者輸入保持原樣，不做翻譯。
