# 快速開始

`@openviking/react` 是 OpenViking 的 React 元件庫，提供檔案樹、檔案預覽、命令控制台、對話、登入表單和看板等[業務元件](../components/)，以及自帶資料載入的[區塊](../modules/)。文件裡的「宿主」指嵌入這些元件的你的應用。

## 安裝

```bash
npm install @openviking/react
```

`react` 和 `react-dom` 是 peer 依賴，版本範圍是 `^18.2.0 || ^19.0.0`。包只提供 ESM 入口。

FilePreview 和 VikingBot 用可選 peer 依賴 `@ark-design/ui` 渲染，內建它們的 FileBrowser 和 Console 同樣需要。版本和配套包見 [FilePreview](../components/file-preview) 與 [VikingBot](../components/viking-bot) 頁面的「引入」。

## 引入樣式

JavaScript 匯入不會自動載入 CSS，按需選擇一個樣式入口：

```ts
// 整個元件庫：全部業務元件、區塊和主題
import '@openviking/react/style.css';

// 全部業務元件，或全部區塊
import '@openviking/react/components/style.css';
import '@openviking/react/modules/style.css';

// 單個業務元件或區塊
import '@openviking/react/components/file-tree/style.css';
import '@openviking/react/modules/file-browser/style.css';
```

每個入口都可以單獨使用，並已包含所用元件的樣式。圖示（`@openviking/react/icons`）不需要樣式表。

## 使用一個業務元件

業務元件是純檢視：資料由你傳入，使用者的操作通過回撥交給宿主，元件不發起請求。下面的 FileTree 把你提供的行渲染成檔案樹：

```tsx
import { useState } from 'react';
import {
  FileTree,
  type FileTreeRow,
} from '@openviking/react/components/file-tree';
import '@openviking/react/components/file-tree/style.css';

const rows: FileTreeRow[] = [
  {
    kind: 'entry',
    id: 'viking://resources',
    uri: 'viking://resources',
    name: 'resources',
    type: 'directory',
    depth: 0,
    expanded: true,
  },
  {
    kind: 'entry',
    id: 'viking://resources/intro.md',
    uri: 'viking://resources/intro.md',
    name: 'intro.md',
    type: 'file',
    depth: 1,
  },
];

export function Tree() {
  const [selectedId, setSelectedId] = useState<string>();
  return (
    <div style={{ height: 320 }}>
      <FileTree
        rows={rows}
        selectedId={selectedId}
        search={false}
        refresh={false}
        operations={{ select: async (row) => setSelectedId(row.id) }}
      />
    </div>
  );
}
```

FileTree 的高度是父容器的 100%，所以外層要設定高度。示例沒有提供搜尋和重新整理的實現，用 `search={false}` 和 `refresh={false}` 隱藏了這兩個入口。

匯入規則：

- 元件和它的型別從 `@openviking/react/components/<名稱>` 匯入，例如 `file-tree`，每個元件的確切路徑見它頁面的「引入」。
- 根入口 `@openviking/react` 也匯出元件本體和主 Props 型別，例如 `FileTree` 和 `FileTreeProps`；其餘型別只從子路徑匯入。
- FilePreview 是例外：它依賴可選 peer `@ark-design/ui`，只從 `@openviking/react/components/file-preview` 子路徑匯出，不在根入口裡。

## 使用一個區塊

FileBrowser 和 Console 自己讀取 OpenViking 原生 API，需要放在 `OpenVikingProvider` 內，由 Provider 提供服務地址和憑證。下面以 FileBrowser 為例：

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { FileBrowser } from '@openviking/react/modules/file-browser';
import '@openviking/react/modules/file-browser/style.css';

export function Browser({ apiKey }: { apiKey: string }) {
  return (
    <OpenVikingProvider baseURL="https://ov.example.com" apiKey={apiKey}>
      <div style={{ height: 600 }}>
        <FileBrowser />
      </div>
    </OpenVikingProvider>
  );
}
```

- `baseURL` 是服務地址，不含 `/api/v1`。
- FileBrowser 的高度是父容器的 100%，外層要設定高度。
- FileBrowser 預覽檔案內容需要先安裝可選 peer 依賴 `@ark-design/ui`，見上文「安裝」。
- 登入、帳號作用域和路由由宿主負責。
- 其餘身份欄位、`requestOptions` 和各區塊的規則見[區塊](../modules/)。

## 自定義錯誤展示

FilePreview、CommandConsole、VikingBot 及其訊息列表、輸入區和互動表單、兩個看板，以及 FileBrowser、Console 和 ScopeCascade 區塊，均支援可選的 `slots.errorFallback: ReactNode | ((reset: () => void) => ReactNode)`。它替換渲染異常後的整個錯誤展示，宿主可在傳入的內容上設定 `className`、`style` 和自己的互動。

```tsx
<FileBrowser
  slots={{
    errorFallback: (reset) => (
      <div className="my-error" role="alert">
        檔案區域暫不可用
        <button type="button" onClick={reset}>
          重新顯示
        </button>
      </div>
    ),
  }}
/>
```

- 不傳或傳 `undefined`：繼承外層元件或區塊的配置；沒有外層配置時使用內建的區域文案和“重試顯示”。
- 內部區域：預設繼承，子元件顯式設定的插槽優先；FilePreview 的頁籤 `slots.errorFallback` 優先於元件級配置。
- 傳 `null`：隱藏對應渲染錯誤展示；自定義內容會替換內建提示和重試按鈕。

渲染函式在失敗時收到當前區域的 `reset`。呼叫它會清除該區域的錯誤狀態並重新渲染，不會重置外層狀態或主動重發業務請求；原因仍未消除時，會再次顯示 fallback。函式繼承到內部區域時，收到的是該內部區域自己的 `reset`。

插槽變化只更新失敗展示，不會自動重試或清空邊界外的狀態。它僅影響渲染異常；普通請求失敗繼續使用各元件原有的錯誤態配置。錯誤邊界本身仍是庫內實現。

## 主題

元件的顏色讀取 `--ov-ui-color-*` 變數。庫本身不定義這些變數：在應用根節點或任意祖先元素上設定它們，元件就使用你的值；沒有設定時，元件使用內建的預設色。

```css
.my-workbench {
  --ov-ui-color-primary: #0f766e;
  --ov-ui-color-bg-5: #eef5f4;
  --ov-ui-color-border-2: #d4e4e1;
}
```

寫在 `:root` 上則對整個應用生效。帶有「主題變數」一節的元件頁會列出該元件讀取的變數。

暗色只認 `<html>` 上的 `.dark` 類，不讀 `prefers-color-scheme`，因為系統偏好可能與你的應用實際呈現的主題不一致。出現 `.dark` 後，元件自動切換到內建的暗色預設值。你設定的變數在亮色和暗色下都生效，需要暗色專用的值時，在 `.dark` 下再宣告一次：

```css
.dark .my-workbench {
  --ov-ui-color-primary: #5eead4;
}
```

只想調整單個元件時，覆蓋它的 `--ov-ui-<元件>-*` 變數。這些變數宣告在元件的根元素上，設定在祖先元素上不會生效，要寫在元件自己的選擇器上：

```css
.my-workbench .ov-file-tree {
  --ov-ui-file-tree-row-height: 28px;
}
```
