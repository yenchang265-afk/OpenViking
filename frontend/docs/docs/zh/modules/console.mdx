# Console 互動面板

在一塊麵板裡提供對話和命令兩種模式：對話模式接通原生 VikingBot 對話；命令模式把 `ov` 命令傳送到 OpenViking 原生 API 並展示結果。

## 何時使用

- 需要一塊讓使用者既能和 VikingBot 對話，又能用 `ov` 命令瀏覽、檢索和寫入知識庫的面板。
- 需要在瀏覽器裡執行 OpenViking 原生 API 命令，並在切換模式時保留命令記錄和輸入草稿。
- 只需要對話檢視或命令輸入區時，使用 [VikingBot](../components/viking-bot) 或 [CommandConsole](../components/command-console)；需要自己提供命令目錄時也使用後者，Console 的命令是內建的。

## 引入

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { Console } from '@openviking/react/modules/console';
import '@openviking/react/modules/console/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <Console />
</OpenVikingProvider>;
```

樣式入口已包含 CommandConsole 和 VikingBot 的樣式。Provider 與請求配置的規則見[區塊概覽](./)。

對話模式使用 [VikingBot](../components/viking-bot)，它依賴可選 peer 依賴 `@ark-design/ui`，不會隨 `@openviking/react` 自動安裝，安裝方式見該頁的「引入」。

### 內建對話

省略 `conversation.messages`、`conversation.onSend` 和 `conversation.composer` 時，Console 內部管理請求、訊息和輸入框。宿主仍可提供文案、插槽與 `conversation.sessions`：其 `items`、載入及錯誤資訊用於展示，`currentId` 可同步路由；每次主動選擇歷史會話（包括重新選擇當前會話）都通過 `onSelect` 通知一次，非同步建立的會話 ID 也通過 `onSelect` 同步。每次主動新建通過 `onNew` 通知，即使遠端會話尚未建立。宿主將新建 ID 寫回 `currentId` 不會重啟正在進行的回覆。切換會話會清空舊草稿，已取消的請求不會將其恢復到新會話。

請求、會話和流式狀態由 Console 內部管理；可通過 `chatOptions.service` 適配其他後端，服務同時實現對話與會話契約。模組切換保留當前對話；新建或切換會話會取消舊連線。歷史儲存失敗單獨提示，不改變已成功的回答。

```tsx file="../../_demos/console-chat.tsx" preview

```

示例使用模擬服務，可切換原生能力與火山當前契約。原生介面卡提供 `interrupt` 和 `steer`，支援停止及生成中追問；火山當前介面卡省略這兩個方法，生成中停用傳送且不顯示停止。回答後的下一輪提問兩者均支援。

### 後臺任務

終端提交 `ov add-resource https://example.com/demo`，再切換對話模式傳送任意文字，兩條記錄會跟蹤同一個模擬任務。點選「模擬完成」或「模擬失敗」後檢視狀態更新。

### 功能選擇

`modes={['command']}` 只啟用 TUI，`modes={['conversation']}` 只啟用 VikingBot。省略時兩者都啟用；單功能時隱藏模式切換，關閉的模式不渲染，也不發起請求。當前 `mode` 或 `defaultMode` 不在啟用列表時，顯示列表第一項，不觸發 `onModeChange`。切換模式保留對話；從 `modes` 中移除對話會中止連線，重新啟用時重新載入會話。

### VikingBotChatEvent

| 引數        | 說明                                                         | 型別                                                                                                             | 預設值 |
| ----------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | ------ |
| reasoning   | delta=true 追加；false 替換；id 可選，穩定 ID 更新同一推理項 | `{ type: 'reasoning'; text: string; delta: boolean; id?: string }`                                               | -      |
| text        | delta=true 追加正文；false 替換當前正文片段                  | `{ type: 'text'; text: string; delta: boolean }`                                                                 | -      |
| iteration   | 下一次模型迭代邊界；將已接受追問歸入新的交流段               | `{ type: 'iteration'; iteration: number }`                                                                       | -      |
| tool        | 每次實際呼叫唯一 ID；相同引數也不得合併                      | `{ type: 'tool'; part: VikingBotToolPart }`                                                                      | -      |
| tool-result | 通過 id 對應呼叫；原生無 ID 協議按 FIFO 配對                 | `{ type: 'tool-result'; id: string; output: string; isError?: boolean; tasks?: readonly ConsoleTaskSnapshot[] }` | -      |
| complete    | 正常結束；可選 text 是最終正文快照                           | `{ type: 'complete'; text?: string }`                                                                            | -      |
| interrupted | 中斷終止，保留已有內容                                       | `{ type: 'interrupted' }`                                                                                        | -      |

Console 按介面卡是否提供方法決定停止與追問能力。`steer` 返回 `accepted: false` 表示未接受輸入；不要發出虛假的使用者訊息。事件流沒有終止事件就結束會報 `BOT_STREAM_TRUNCATED`。

`tool-result.tasks` 宣告工具實際發起的後臺任務，包含必填 `id` 及可選 `kind`、`uri`、`status`。原生介面卡從已知提交工具的結構化結果中提取任務 ID，其他服務直接提供 `tasks`。工具返回、聊天回覆結束與後臺任務完成分別處理，工具片段保留原始輸出並展示任務快照。

### ConsoleTaskSnapshot

| 引數       | 說明                                       | 型別                                                                               | 預設值 |
| ---------- | ------------------------------------------ | ---------------------------------------------------------------------------------- | ------ |
| id         | 後臺任務 ID                                | `string`                                                                           | 必填   |
| status     | 任務狀態，查詢結果必須提供                 | `'pending' \| 'running' \| 'cancelling' \| 'completed' \| 'failed' \| 'cancelled'` | -      |
| kind       | 任務類別，用於通知標題                     | `'resource' \| 'skill' \| 'memory' \| 'compile'`                                   | -      |
| uri        | 任務關聯的資源 URI                         | `string`                                                                           | -      |
| stage      | 服務端返回的執行階段                       | `string`                                                                           | -      |
| result     | 服務端返回的任務結果                       | `unknown`                                                                          | -      |
| error      | 服務端返回的任務錯誤                       | `string`                                                                           | -      |
| queryError | 排程器生成的查詢錯誤，保留最後一次任務狀態 | `{ code: 'request' \| 'invalid-response'; message?: string }`                      | -      |

排程器每 3 秒查詢一次活躍任務，同一作用域和任務 ID 只保留一個查詢，最多併發 4 個請求。查詢失敗指數退避至最多 30 秒，到達終態後停止。進行中的任務通知使用內建 loading 圖示，到達終態後替換為結果圖示；查詢異常顯示警告，不改變任務狀態。

切換模式或聊天會話、清空終端記錄、關閉通知均不取消後臺任務。關閉通知後仍更新關聯記錄；切換身份或解除安裝 Console 會中止查詢並忽略舊響應。通知與任務狀態不跨頁面重新整理持久化。

其他後端通過 `taskService` 適配請求和狀態欄位。該物件及 `chatOptions.taskService` 應保持引用穩定；後者可覆蓋對話任務的查詢方式。不同服務、身份或 `scopeKey` 的任務分別跟蹤。宿主完全控制 `conversation` 時，任務狀態也由宿主提供。

## 命令

命令模式只執行內建的原生 API 命令。輸入 `/` 或執行 `ov help`，可以按「核心流程」「檔案系統」「搜尋與上下文」「配置與狀態」檢視命令和各自的選項。

### 寫法

- 命令可以寫成 `ov find`、`/find`，也可以直接寫 `find`。
- 含空格的引數用單引號或雙引號包住，也可以用反斜線轉義。
- 以 `--` 開頭的值要加引號，例如 `ov write viking://resources/a.md "--heading"`；也可以用 `--` 結束選項解析，例如 `ov write viking://resources/a.md -- --heading`。選項值同理，例如 `--description "--example"`。
- 引數按資料解析，不執行 Shell。未加引號的 `| ; & < > $` 和反引號會被拒絕，含 `&` 的 URL 要加引號。
- 未知選項、重複選項、缺少引數、不以 `viking://` 開頭的 URI 和未閉合的引號都會生成失敗記錄，不傳送請求。

### 支援的命令

| 能力       | 命令                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 新增與編譯 | `add-resource <path>`、`add-skill <path>`、`add-memory <content> --session-id <session-id>`、`compile --from <from> --to <to>`、`compile create --from <from> --to <to>` |
| 本地       | `help`、`clear`                                                                                                                                                          |
| 服務       | `health`、`status`                                                                                                                                                       |
| 瀏覽       | `ls [uri]`、`tree [uri]`、`stat <uri>`                                                                                                                                   |
| 內容       | `read <uri>`、`abstract <uri>`、`overview <uri>`                                                                                                                         |
| 檢索       | `find <query>`、`search <query>`、`grep <pattern>`、`glob <pattern>`                                                                                                     |
| 寫入       | `mkdir <uri>`、`write <uri> <content>`、`cp <from_uri> <to_uri>`、`mv <from_uri> <to_uri>`、`rm <uri>`                                                                   |
| 任務       | `task list`、`task status <id>`、`task cancel <id>`                                                                                                                      |

- `ls` 和 `tree` 預設從 `viking://` 開始，最多返回 100 條；用 `--limit` 和 `--offset` 分頁，`tree` 另有 `--level_limit`。
- `write` 預設覆蓋已有內容；`--mode create` 表示建立，`--mode append` 表示追加。
- `add-resource` 和 `add-skill` 接受遠端地址，不接受本地檔案路徑。
- `add-memory` 把內容作為使用者訊息追加到 `--session-id` 指定的會話，再提交該會話。
- `compile` 預設使用內建的 llm-wiki Skill，用 `--skill` 指定其他 Skill；`compile create` 只儲存編譯配置，不啟動編譯。
- `task cancel` 向服務端請求協作取消，任務可能不會立即停止。
- 選項名的寫法因命令而異，例如 `add-skill` 用 `--target-uri`，`find` 用 `--target_uri`，以 `ov help` 為準。
- 匯入、編譯與記憶提交返回任務 ID 後自動跟蹤；任務狀態獨立於提交結果，終端輸入在提交請求返回後恢復可用。
- 命令集只包含瀏覽器能呼叫的原生 API，本地配置、登入、本地檔案上傳下載和會話管理類命令不在其中。

## 注意

傳送失敗的提問和客戶端錯誤保留在訊息列表中。會話尚未建立時，下次傳送會補建會話，將未送達的使用者輸入作為上下文合併到同一次聊天請求，分別儲存原始使用者訊息；錯誤提示不會儲存或傳送給模型。原生閘道器只接收單條 `message`，因此僅補寫會話訊息不能恢復模型上下文。 未送達的輸入會保留到收到首個流事件；在此之前失敗，下次傳送仍會攜帶這些上下文。生成開始後不再重放舊輸入。

- 預設傳送原生 VikingBot 對話請求。傳入 `conversation.messages` 或 `conversation.onSend` 時改由宿主管理對話；附件上傳仍由宿主完成。
- 宿主查詢 Bot 狀態後設置 `conversation.isAvailable` 和 `conversation.unavailableMessage`，不可用時輸入區被停用並顯示說明。
- 命令只在使用者提交時傳送請求，掛載時不請求。同一例項一次只執行一條命令，執行期間輸入框被停用。
- 命令失敗時，錯誤顯示在對應的記錄裡，修正後重新提交即可；寫入類命令失敗時服務端可能已經接收，重新提交前先核對結果。
- 命令模式的「新建會話」會中止進行中的請求並忽略遲到的響應，同時清空命令記錄、錯誤和輸入框；服務端已接收的操作不會撤銷，服務端資料也不會刪除。`clear` 命令只清空本地記錄。
- 命令歷史列出當前面板的記錄，最新的在前，時間為提交時的本地時間（`YYYY-MM-DD HH:mm`）；點選一條會把命令填回輸入框，不會執行。
- 命令記錄和草稿只儲存在記憶體中。`scopeKey`、`requestOptions` 或 Provider 的配置變化時，Console 清空記錄和草稿並中止進行中的請求，解除安裝時同樣中止。
- 身份欄位使用函式時，保持函式引用穩定，並在身份變化時更新 `scopeKey`，或用身份作為元件的 `key`。
- Console 撐滿父容器的寬高，父容器需要有明確的高度，或是可伸展的 flex 佈局。
- 切換 `locale` 會更新已有記錄裡的命令幫助、引數錯誤和取消提示，保留記錄和草稿；服務端返回的內容保持原樣。
- 認證、帳號切換和頁面佈局由宿主負責。`onOpenUri` 只上報資源連結的開啟意圖，導航由宿主完成。
- 型別從 `@openviking/react/modules/console` 匯出，包根入口只匯出 `Console` 和 `ConsoleProps`。
