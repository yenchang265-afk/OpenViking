# Console 互動面板

在一塊麵板裡提供對話和命令兩種模式：對話模式通過 [VikingBot 無頭模組](./viking-bot) 接通原生對話；命令模式把 `ov` 命令傳送到 OpenViking 原生 API 並展示結果。

## 何時使用

- 需要一塊讓使用者既能和 VikingBot 對話，又能用 `ov` 命令瀏覽、檢索和寫入知識庫的面板。
- 需要在瀏覽器裡執行 OpenViking 原生 API 命令，並在切換模式時保留命令記錄和輸入草稿。
- 只需要對話檢視或命令輸入區時，使用 [VikingBot](../components/viking-bot) 或 [CommandConsole](../components/command-console)；需要自己提供命令目錄時也使用後者，Console 的命令是內建的。

## 引入

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { Console } from '@openviking/react/modules/console';
import '@openviking/react/modules/console/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <Console />
</OpenVikingProvider>;
```

樣式入口已包含 CommandConsole 和 VikingBot 的樣式。Provider 與請求配置的規則見[區塊概覽](./)。

對話模式使用 [VikingBot](../components/viking-bot)，它依賴可選 peer 依賴 `@ark-design/ui`，不會隨 `@openviking/react` 自動安裝，安裝方式見該頁的「引入」。

### 基礎用法

面板預設進入對話模式；切換到「終端」，輸入 `ov ls viking://resources/demo` 或 `ov read viking://resources/demo/notes.md`，點選結果裡的資源連結，面板下方會顯示 `onOpenUri` 收到的 URI。

### 內建對話

預設使用 `modules/viking-bot` 的兩個 Hook；可通過 `chatOptions.service` 適配其他後端，服務同時實現對話與會話契約。模組切換保留當前對話；新建或切換會話會取消舊連線。歷史儲存失敗單獨提示，不改變已成功的回答。

## 命令

命令模式只執行內建的原生 API 命令。輸入 `/` 或執行 `ov help`，可以按「核心流程」「檔案系統」「搜尋與上下文」「配置與狀態」檢視命令和各自的選項。

### 寫法

- 命令可以寫成 `ov find`、`/find`，也可以直接寫 `find`。
- 含空格的引數用單引號或雙引號包住，也可以用反斜線轉義。
- 以 `--` 開頭的值要加引號，例如 `ov write viking://resources/a.md "--heading"`；也可以用 `--` 結束選項解析，例如 `ov write viking://resources/a.md -- --heading`。選項值同理，例如 `--description "--example"`。
- 引數按資料解析，不執行 Shell。未加引號的 `| ; & < > $` 和反引號會被拒絕，含 `&` 的 URL 要加引號。
- 未知選項、重複選項、缺少引數、不以 `viking://` 開頭的 URI 和未閉合的引號都會生成失敗記錄，不傳送請求。

### 支援的命令

| 能力       | 命令                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 新增與編譯 | `add-resource <path>`、`add-skill <path>`、`add-memory <content> --session-id <session-id>`、`compile --from <from> --to <to>`、`compile create --from <from> --to <to>` |
| 本地       | `help`、`clear`                                                                                                                                                          |
| 服務       | `health`、`status`                                                                                                                                                       |
| 瀏覽       | `ls [uri]`、`tree [uri]`、`stat <uri>`                                                                                                                                   |
| 內容       | `read <uri>`、`abstract <uri>`、`overview <uri>`                                                                                                                         |
| 檢索       | `find <query>`、`search <query>`、`grep <pattern>`、`glob <pattern>`                                                                                                     |
| 寫入       | `mkdir <uri>`、`write <uri> <content>`、`cp <from_uri> <to_uri>`、`mv <from_uri> <to_uri>`、`rm <uri>`                                                                   |
| 任務       | `task list`、`task status <id>`、`task cancel <id>`                                                                                                                      |

- `ls` 和 `tree` 預設從 `viking://` 開始，最多返回 100 條；用 `--limit` 和 `--offset` 分頁，`tree` 另有 `--level_limit`。
- `write` 預設覆蓋已有內容；`--mode create` 表示建立，`--mode append` 表示追加。
- `add-resource` 和 `add-skill` 接受遠端地址，不接受本地檔案路徑。
- `add-memory` 把內容作為使用者訊息追加到 `--session-id` 指定的會話，再提交該會話。
- `compile` 預設使用內建的 llm-wiki Skill，用 `--skill` 指定其他 Skill；`compile create` 只儲存編譯配置，不啟動編譯。
- `task cancel` 向服務端請求協作取消，任務可能不會立即停止。
- 選項名的寫法因命令而異，例如 `add-skill` 用 `--target-uri`，`find` 用 `--target_uri`，以 `ov help` 為準。
- 命令顯示介面返回的結果；匯入、編譯等非同步操作的最終狀態用 `task status <id>` 查詢。
- 命令集只包含瀏覽器能呼叫的原生 API，本地配置、登入、本地檔案上傳下載和會話管理類命令不在其中。

## 注意

- 預設使用 VikingBot 無頭模組傳送原生對話請求。傳入 `conversation.messages` 或 `conversation.onSend` 時改由宿主管理對話；附件上傳仍由宿主完成。
- 宿主查詢 Bot 狀態後設置 `conversation.isAvailable` 和 `conversation.unavailableMessage`，不可用時輸入區被停用並顯示說明。
- 命令只在使用者提交時傳送請求，掛載時不請求。同一例項一次只執行一條命令，執行期間輸入框被停用。
- 命令失敗時，錯誤顯示在對應的記錄裡，修正後重新提交即可；寫入類命令失敗時服務端可能已經接收，重新提交前先核對結果。
- 命令模式的「新建會話」會中止進行中的請求並忽略遲到的響應，同時清空命令記錄、錯誤和輸入框；服務端已接收的操作不會撤銷，服務端資料也不會刪除。`clear` 命令只清空本地記錄。
- 命令歷史列出當前面板的記錄，最新的在前，時間為提交時的本地時間（`YYYY-MM-DD HH:mm`）；點選一條會把命令填回輸入框，不會執行。
- 命令記錄和草稿只儲存在記憶體中。`scopeKey`、`requestOptions` 或 Provider 的配置變化時，Console 清空記錄和草稿並中止進行中的請求，解除安裝時同樣中止。
- 身份欄位使用函式時，保持函式引用穩定，並在身份變化時更新 `scopeKey`，或用身份作為元件的 `key`。
- Console 撐滿父容器的寬高，父容器需要有明確的高度，或是可伸展的 flex 佈局。
- 切換 `locale` 會更新已有記錄裡的命令幫助、引數錯誤和取消提示，保留記錄和草稿；服務端返回的內容保持原樣。
- 認證、帳號切換和頁面佈局由宿主負責。`onOpenUri` 只上報資源連結的開啟意圖，導航由宿主完成。
- 型別從 `@openviking/react/modules/console` 匯出，包根入口只匯出 `Console` 和 `ConsoleProps`。
