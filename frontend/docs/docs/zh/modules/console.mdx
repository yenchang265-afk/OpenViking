# Console 互動面板

在一塊麵板裡提供對話和命令兩種模式：對話模式接通原生 VikingBot 對話；命令模式把 `ov` 命令傳送到 OpenViking 原生 API 並展示結果。

## 何時使用

- 需要一塊讓使用者既能和 VikingBot 對話，又能用 `ov` 命令瀏覽、檢索和寫入知識庫的面板。
- 需要在瀏覽器裡執行 OpenViking 原生 API 命令，並在切換模式時保留命令記錄和輸入草稿。
- 只需要對話檢視或命令輸入區時，使用 [VikingBot](../components/viking-bot) 或 [CommandConsole](../components/command-console)；需要自己提供命令目錄時也使用後者，Console 的命令是內建的。

## 引入

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { Console } from '@openviking/react/modules/console';
import '@openviking/react/modules/console/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <Console />
</OpenVikingProvider>;
```

樣式入口已包含 CommandConsole 和 VikingBot 的樣式。Provider 與請求配置的規則見[區塊概覽](./)。

對話模式使用 [VikingBot](../components/viking-bot)，它依賴可選 peer 依賴 `@ark-design/ui`，不會隨 `@openviking/react` 自動安裝，安裝方式見該頁的「引入」。

### 內建對話

省略 `conversation.messages`、`conversation.onSend` 和 `conversation.composer` 時，Console 內部管理請求、訊息和輸入框。宿主仍可提供文案、插槽與 `conversation.sessions`：其 `items`、載入及錯誤資訊用於展示，`currentId` 可同步路由；每次主動選擇歷史會話（包括重新選擇當前會話）都通過 `onSelect` 通知一次，非同步建立的會話 ID 也通過 `onSelect` 同步。每次主動新建通過 `onNew` 通知，即使遠端會話尚未建立。宿主將新建 ID 寫回 `currentId` 不會重啟正在進行的回覆。切換會話會清空舊草稿，已取消的請求不會將其恢復到新會話。

請求、會話和流式狀態由 Console 內部管理；可通過 `chatOptions.service` 適配其他後端，服務同時實現對話與會話契約。模組切換保留當前對話；新建或切換會話會取消舊連線。歷史儲存失敗單獨提示，不改變已成功的回答。

點選「建立 Wiki」或「定時日報」可填入空白草稿或切換預設。傳送後由配置的對話服務處理請求，編譯相關的確認問題通過下方介紹的流程展示。用 `conversation.quickInputs` 提供自定義列表，傳入 `[]` 可隱藏快捷入口。


示例使用模擬服務，可切換原生能力與火山當前契約。原生介面卡提供 `interrupt` 和 `steer`，支援停止及生成中追問；火山當前介面卡省略這兩個方法，生成中停用傳送且不顯示停止。回答後的下一輪提問兩者均支援。

點選底部的 `@`，或在輸入框中鍵入 `@`，可瀏覽、搜尋並引用檔案和目錄。內建選擇器使用當前請求作用域下的 `/api/v1/fs/ls` 和 `/api/v1/search/glob`，開啟時才載入。通過 `chatOptions.referenceSelection` 傳入 `{ selected, onChange }`，可以讓目錄樹與內建 `@` 選擇器共享已選引用。傳送後由宿主移除已傳送的引用，重置會話時由 Console 清空已選引用。設定 `conversation.references` 可自行提供候選項和已選引用，替代內建選擇器。自定義對話服務可通過傳送引數中的 `references` 讀取已選引用。

### 待確認互動

傳送任意訊息觸發模擬問題組。示例為名稱注入非同步校驗、為輸出目錄提供選擇器，並用自定義元件替換指令卡片；定時的外部規則將更新時間限制在 09:00–18:00。勾選「模擬答案發送失敗」可檢查輸入保留、錯誤清理與重試。

```tsx file="../../_demos/console-hitl.tsx" preview

```

Console 在 `request_user_input` 工具成功且當前輪正常結束後展示問題，按問題組順序收集答案。中斷、截斷、錯誤結果和不支援的協議保留普通工具展示。傳入 `chatOptions.hitl={false}` 關閉自動互動；顯式傳入 `conversation.interaction` 時使用宿主的問題與回撥。

歷史訊息不包含可確認的輪次終止狀態，載入歷史只恢復訊息和答案摘要，不重新觸發問題卡片。新一輪即時回覆正常結束後仍可觸發互動。

最後一項提交後，Console 傳送 `request_user_input_response` JSON 繼續下一輪對話，包含 `schema_version: '1.0'`、`tool_call_id` 和按原順序排列的 `answers: { card_type, title, value }[]`。使用者氣泡、複製和歷史展示採用標籤/值摘要；傳送與儲存保留協議原文，選項名稱從對應問題中恢復。

宿主通過 `chatOptions.hitl.cards[card_type]` 提供擴充套件。同一型別的多個問題可用 `configureCard(card)` 按 `card.id` 或 `card.payload` 分別配置。欄位名與值型別見 [VikingBotInteractionFields](../components/viking-bot#vikingbotinteractionfields)。校驗通過後才進入下一項，最後一項才呼叫對話服務。目錄存在性、許可權和業務規則由宿主校驗器檢查；自定義選擇器的資料與請求由宿主提供。

### 功能選擇

`modes={['command']}` 只啟用 TUI，`modes={['conversation']}` 只啟用 VikingBot。省略時兩者都啟用；單功能時隱藏模式切換，關閉的模式不渲染，也不發起請求。當前 `mode` 或 `defaultMode` 不在啟用列表時，顯示列表第一項，不觸發 `onModeChange`。切換模式保留對話；從 `modes` 中移除對話會中止連線，重新啟用時重新載入會話。

#### 內建卡片

| card_type           | 預設表單欄位              | 協議中的 value                                                 |
| ------------------- | ------------------------- | -------------------------------------------------------------- |
| compile_name        | `value`，文本             | `string`                                                       |
| compile_output_type | `value`，單選             | 選項的 `value`                                                 |
| compile_source      | `value`，每行一個目錄 URI | 去空行、去重後的 `string[]`                                    |
| compile_target      | `value`，目錄 URI         | `string`                                                       |
| compile_skill       | `value`，候選或自定義 URI | `string`                                                       |
| compile_instruction | `value`，多行文本         | `string`                                                       |
| compile_schedule    | `mode`、`time`、`weekday` | `{ frequency: 'disabled' }` 或包含頻率、時間、星期和時區的物件 |

工具結果支援直接 JSON、MCP `structuredContent` 或文本 `content`，`schema_version` 必須為 `'1.0'`。優先讀取 `structuredContent`；一組中任一問題無效或未註冊時，整組保留為工具結果。原生服務接受裸工具名及 `mcp_openviking-mcp_request_user_input`；自定義介面卡應保留工具呼叫的唯一 `id`，將服務名設為 `openviking-mcp`、工具名設為 `request_user_input`。

`createRequest` 可返回 `kind: 'custom'`，由自定義元件通過 `context.submit(value)` 提交物件或其他答案，並自行管理其欄位校驗。配置 `serialize` 適配服務端值，配置 `summarize` 提供可讀展示；未知型別需提供 `createRequest` 才會觸發互動。

### VikingBotChatService

| 引數             | 說明                                                                     | 型別                                                                                    | 預設值 |
| ---------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- | ------ |
| stream           | 流式請求；必須發出 complete 或 interrupted 終止事件                      | `(input: VikingBotChatInput, signal: AbortSignal) => AsyncIterable<VikingBotChatEvent>` | 必填   |

| loadMessages     | 讀取完整會話歷史                                                         | `(id: string, signal: AbortSignal) => Promise<readonly VikingBotMessage[]>`             | 必填   |
| attachmentUpload | 啟用新增資源按鈕；傳送時將 `upload` 返回的標識傳給 `attachment.uploadId` | `VikingBotAttachmentUpload`                                                             | 可選   |
| saveMessage      | 逐條儲存；後端自動持久化時省略，避免重複                                 | `(id: string, message: VikingBotMessage, signal: AbortSignal) => Promise<void>`         | 可選   |
| interrupt        | 實際中斷後端生成；與本地斷開連線不同                                     | `(id: string, signal: AbortSignal) => Promise<{ interrupted: boolean }>`                | 可選   |
| steer            | 向當前流追加輸入；accepted 僅表示接受，不表示回覆完成                    | `(input: VikingBotChatInput, signal: AbortSignal) => Promise<{ accepted: boolean }>`    | 可選   |

`VikingBotAttachmentUpload` 接收可選的檔案選擇器過濾器 `accept`，以及必填的 `upload(file, signal)`，它返回已上傳檔案的標識。檔案選擇器不會過濾拖入的檔案，介面卡仍需驗證檔案。附件上傳完成後才可傳送。移除附件會取消該檔案的上傳；切換帳號、請求身份或會話，或取消請求訊號時，會取消待完成的上傳並清空託管附件。通過 `conversation.sessions.currentId` 回寫新建會話 ID 時，會保留該會話的正常上傳。如果宿主提供草稿附件或檔案選擇回撥，則使用宿主的配置。

### VikingBotChatEvent

| 引數        | 說明                                                         | 型別                                                                                                             | 預設值 |
| ----------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | ------ |
| reasoning   | delta=true 追加；false 替換；id 可選，穩定 ID 更新同一推理項 | `{ type: 'reasoning'; text: string; delta: boolean; id?: string }`                                               | -      |
| text        | delta=true 追加正文；false 替換當前正文片段                  | `{ type: 'text'; text: string; delta: boolean }`                                                                 | -      |
| iteration   | 下一次模型迭代邊界；將已接受追問歸入新的交流段               | `{ type: 'iteration'; iteration: number }`                                                                       | -      |
| tool        | 每次實際呼叫唯一 ID；相同引數也不得合併                      | `{ type: 'tool'; part: VikingBotToolPart }`                                                                      | -      |
| tool-result | 通過 id 對應呼叫；原生無 ID 協議按 FIFO 配對                 | `{ type: 'tool-result'; id: string; output: string; isError?: boolean; tasks?: readonly ConsoleTaskSnapshot[] }` | -      |
| complete    | 正常結束；可選 text 是最終正文快照                           | `{ type: 'complete'; text?: string }`                                                                            | -      |
| interrupted | 中斷終止，保留已有內容                                       | `{ type: 'interrupted' }`                                                                                        | -      |

Console 按介面卡是否提供方法決定停止與追問能力。`steer` 返回 `accepted: false` 表示未接受輸入；不要發出虛假的使用者訊息。事件流沒有終止事件就結束會報 `BOT_STREAM_TRUNCATED`。

`tool-result.tasks` 宣告工具實際發起的後臺任務，包含必填 `id` 及可選 `kind`、`uri`、`status`。原生介面卡從已知提交工具的結構化結果中提取任務 ID，其他服務直接提供 `tasks`。工具返回、聊天回覆結束與後臺任務完成分別處理，工具片段保留原始輸出並展示任務快照。

### ConsoleTaskSnapshot

| 引數       | 說明                                       | 型別                                                                               | 預設值 |
| ---------- | ------------------------------------------ | ---------------------------------------------------------------------------------- | ------ |
| id         | 後臺任務 ID                                | `string`                                                                           | 必填   |
| status     | 任務狀態，查詢結果必須提供                 | `'pending' \| 'running' \| 'cancelling' \| 'completed' \| 'failed' \| 'cancelled'` | -      |
| kind       | 任務類別，用於通知標題                     | `'resource' \| 'skill' \| 'memory' \| 'compile'`                                   | -      |
| uri        | 任務關聯的資源 URI                         | `string`                                                                           | -      |
| stage      | 服務端返回的執行階段                       | `string`                                                                           | -      |
| result     | 服務端返回的任務結果                       | `unknown`                                                                          | -      |
| error      | 服務端返回的任務錯誤                       | `string`                                                                           | -      |
| queryError | 排程器生成的查詢錯誤，保留最後一次任務狀態 | `{ code: 'request' \| 'invalid-response'; message?: string }`                      | -      |

排程器每 3 秒查詢一次活躍任務，同一作用域和任務 ID 只保留一個查詢，最多併發 4 個請求。查詢失敗指數退避至最多 30 秒，到達終態後停止。資源匯入進度顯示在結果記錄中，其他任務還會顯示載入通知。任務到達終態後顯示結果圖示，查詢異常時顯示警告並保留任務狀態。

任務快照優先使用完成結果裡的資源 URI，並以提交任務時的 URI 兜底。自定義任務服務可以在 `uri` 中直接提供最終資源地址。終端任務完成且有資源 URI 時，「檢視結果」會通過 `command.onOpenUri` 或 `Console.onOpenUri` 開啟資源。通知會保留到點選按鈕或關閉。

切換模式或聊天會話、清空終端記錄、關閉通知均不取消後臺任務。關閉通知後仍更新關聯記錄；切換身份或解除安裝 Console 會中止查詢並忽略舊響應。通知與任務狀態不跨頁面重新整理持久化。

其他後端通過 `taskService` 適配請求和狀態欄位。該物件及 `chatOptions.taskService` 應保持引用穩定；後者可覆蓋對話任務的查詢方式。不同服務、身份或 `scopeKey` 的任務分別跟蹤。宿主完全控制 `conversation` 時，任務狀態也由宿主提供。

## 命令

命令模式只執行內建的原生 API 命令。輸入 `/` 或執行 `ov help`，可以按「核心流程」「檔案系統」「搜尋與上下文」「檔案傳輸」「會話」「配置與狀態」檢視命令和各自的選項。

### 寫法

- 命令可以寫成 `ov find`、`/find`，也可以直接寫 `find`。
- 含空格的引數用單引號或雙引號包住，也可以用反斜線轉義。
- 以 `--` 開頭的值要加引號，例如 `ov write viking://resources/a.md --content "--heading"`。傳入位置引數前也可以用 `--` 結束選項解析。短選項區分大小寫。`tree` 中 `-L` 限制樹深度，`-l` 限制摘要長度。
- 引數按資料解析，不執行 Shell。未加引號的 `| ; & < > $` 和反引號會被拒絕，含 `&` 的 URL 要加引號。
- 未知選項、重複的單值選項、缺少引數、無效的資源 URI 和未閉合的引號都會生成失敗記錄，不傳送請求。

### 支援的命令

| 能力       | 命令                                                                                                                                                                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增與編譯 | `add-resource [path-or-url]`、`add-skill [skill-content-or-url]`、`add-memory <content> --session-id <id>`、`compile create --compile-name <name> --from <source-uri> --to <target-uri> --skill <skill-uri>`、`compile --compile-name <name>` |
| 本地       | `help`、`clear`                                                                                                                                                                                                                               |
| 服務       | `health`、`status`                                                                                                                                                                                                                            |
| 瀏覽       | `ls [uri]`、`tree <uri>`、`stat <uri>`                                                                                                                                                                                                        |
| 內容       | `read <uri>`、`abstract <uri>`、`overview <uri>`                                                                                                                                                                                              |
| 檢索       | `find [query]`、`search [query]`、`grep <pattern>`、`glob <pattern>`                                                                                                                                                                          |
| 寫入       | `mkdir <uri>`、`write <uri> --content <text>`、`cp <from-uri> <to-uri>`、`mv <from-uri> <to-uri>`、`rm <uri>`                                                                                                                                 |
| 任務       | `task list [--task-type <type>] [--status <status>]`、`task status <task-id>`、`task cancel <task-id>`                                                                                                                                        |

- `ls` 預設從 `viking://` 開始。`ls` 和 `tree` 用 `-n` 或 `--node-limit` 限制返回條數，預設 256 條，用 `-a` 或 `--all` 包含隱藏檔案。`ls` 支援 `-r` 或 `--recursive` 遞迴列出子目錄，以及 `-s` 或 `--simple` 只返回路徑。用 `ov tree viking://resources -L 2` 或 `ov tree viking://resources --level-limit 2` 控制深度，預設 3 層。已有的 `--offset` 可繼續用於分頁。
- 用 `find` 或 `search` 獲取排序後的結果時，`-u` 或 `--uri` 指定檢索範圍，`-n` 或 `--node-limit` 限制返回條數，`-t` 或 `--threshold` 設定最低分數。兩者都支援用 `--image <url>` 檢索圖片，以及用 `--after` 或 `--before` 按時間篩選。`search --mode context` 用於組裝上下文。`grep` 支援 `-i` 或 `--ignore-case`、`-x` 或 `--exclude-uri`、`-L` 或 `--level-limit`。
- `write` 預設覆蓋已有內容。用 `--mode create` 建立檔案，用 `--append` 追加文本。`mkdir` 和 `write` 支援用 `--acl` 傳入帶引號的 JSON 物件，例如 `ov mkdir viking://resources/demo --acl '{"acl_mode":"inherit","entries":[]}'`。複製或刪除目錄樹時使用 `-r` 或 `--recursive`。
- `add-resource` 支援遠端地址，可用 `--include` 和 `--exclude` 指定過濾條件。`add-resource` 和 `add-skill` 都可以通過 `--temp-file-id <id>` 引用宿主已上傳的檔案。`add-skill` 還支援直接傳入 Skill 內容，用 `-p` 或 `--target-uri` 指定目標位置。
- `add-memory` 把內容作為使用者訊息追加到 `--session-id` 指定的會話，再提交該會話。
- 用 `compile create` 儲存命名配置，再用 `compile --compile-name <name>` 執行。可以重複傳入 `--from`，也可以用英文逗號分隔多個來源目錄 URI。通過 `--instruction` 補充指令，或用 `--args` 傳入模型、定時計劃等 JSON 引數。用 `task status <task-id>` 查詢返回的任務 ID。
- `task cancel` 向服務端請求協作取消，任務可能不會立即停止。
- 匯入、編譯與記憶提交返回任務 ID 後自動跟蹤；任務狀態獨立於提交結果，終端輸入在提交請求返回後恢復可用。
- `session` 支援建立、列表、詳情、上下文、歸檔、訊息寫入、提交和配置。批次訊息用 `ov session add-messages <session-id> '<messages-json>'`。
- `ov get <uri> <local-path>` 和 `ov export <uri> <output.ovpack>` 由瀏覽器下載。輸出路徑的最後一段用作檔名。`export` 和 `backup` 支援 `--include-vectors`。
- `ov import <file.ovpack> <target-uri>` 通過本地檔案選擇器上傳 OVPack，可傳 `--on-conflict` 和 `--vector-mode`。宿主可以通過 `commandOptions.choosePackFile` 複用檔案管理器的匯入彈窗。彈窗只接受有效的 `.ovpack` 檔案。
- `add-resource` 的本地來源以及 `write --from-file` 通過瀏覽器選擇檔案。瀏覽器的本機配置和登入由宿主處理。管理員命令 `backup`、`restore` 預設關閉，由有授權的宿主通過 `commandOptions.allowAdminCommands` 啟用。

## 注意

傳送失敗的提問和客戶端錯誤保留在訊息列表中。會話尚未建立時，下次傳送會補建會話，將未送達的使用者輸入作為上下文合併到同一次聊天請求，分別儲存原始使用者訊息；錯誤提示不會儲存或傳送給模型。原生閘道器只接收單條 `message`，因此僅補寫會話訊息不能恢復模型上下文。 未送達的輸入會保留到收到首個流事件；在此之前失敗，下次傳送仍會攜帶這些上下文。生成開始後不再重放舊輸入。

- 預設傳送原生 VikingBot 對話請求。傳入 `conversation.messages` 或 `conversation.onSend` 時改由宿主管理對話和附件狀態。
- 宿主查詢 Bot 狀態後設置 `conversation.isAvailable` 和 `conversation.unavailableMessage`，不可用時輸入區被停用並顯示說明。
- 命令只在使用者提交時傳送請求，掛載時不請求。同一例項一次只執行一條命令，執行期間輸入框被停用。
- 命令失敗時，錯誤顯示在對應的記錄裡，修正後重新提交即可；寫入類命令失敗時服務端可能已經接收，重新提交前先核對結果。
- 命令模式的「新建會話」會中止進行中的請求並忽略遲到的響應，同時清空命令記錄、錯誤和輸入框；服務端已接收的操作不會撤銷，服務端資料也不會刪除。`clear` 命令只清空本地記錄。
- 命令歷史列出當前面板的記錄，最新的在前，時間為提交時的本地時間（`YYYY-MM-DD HH:mm`）；點選一條會把命令填回輸入框，不會執行。
- 命令記錄和草稿只儲存在記憶體中。`scopeKey`、`requestOptions` 或 Provider 的配置變化時，Console 清空記錄和草稿並中止進行中的請求，解除安裝時同樣中止。
- 設定 `commandHistoryKey` 後，Console 在瀏覽器的會話儲存中在瀏覽器儲存容量內儲存最近最多 50 條有效只讀命令及其提交時間。寫入命令和格式錯誤的命令可在當前頁面回填。「新建會話」清除當前身份範圍的歷史。
- 身份欄位使用函式時，保持函式引用穩定，並在身份變化時更新 `scopeKey`，或用身份作為元件的 `key`。
- Console 撐滿父容器的寬高，父容器需要有明確的高度，或是可伸展的 flex 佈局。
- 切換 `locale` 會更新已有記錄裡的命令幫助、引數錯誤和取消提示，保留記錄和草稿；服務端返回的內容保持原樣。
- 認證、帳號切換和頁面佈局由宿主負責。`onOpenUri` 只上報資源連結的開啟意圖，導航由宿主完成。
- 型別從 `@openviking/react/modules/console` 匯出，包根入口只匯出 `Console` 和 `ConsoleProps`。

原生 VikingBot 的附件在傳送請求前校驗，不符合原有圖片型別或 URL 要求時通過 Toast 提示並保留草稿。自定義 `chatOptions.service` 負責自己的附件契約。
