# FileBrowser 檔案瀏覽

目錄樹、搜尋和檔案預覽組成的檔案瀏覽區塊：讀取 OpenViking 的目錄和內容，支援預覽、編輯、匯入匯出、歷史版本和許可權管理，並內建 Wiki 與經驗看板。

## 何時使用

- 需要在應用裡瀏覽 OpenViking 的上下文目錄（使用者、會話、Agent、資源），並預覽、編輯其中的檔案。
- 希望目錄載入、分頁、預覽和重新整理由區塊協調：區塊通過 `OpenVikingProvider` 請求原生 API，登入、帳號作用域、路由和匯入流程由宿主提供，許可權由服務端校驗。
- 只需要純檢視、資料自己載入時，單獨使用 [FileTree](../components/file-tree) 和 [FilePreview](../components/file-preview)；需要命令面板或對話時使用 [Console](./console)。

## 引入

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { FileBrowser } from '@openviking/react/modules/file-browser';
import '@openviking/react/modules/file-browser/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <FileBrowser />
</OpenVikingProvider>;
```

樣式入口已包含 FileTree、FilePreview、FileBrowserActionBar、WikiDashboard 和 ExperienceDashboard 的樣式。檔案內容由 [FilePreview](../components/file-preview) 渲染，需要先安裝可選的 peer 依賴 `@ark-design/ui`。Provider 與請求配置的規則見[區塊概覽](./)。

## 程式碼演示

### 基礎用法

展示目錄樹、搜尋和預覽的聯動，以及 Wiki 與經驗看板。底部的按鈕切換預覽的資源型別，下拉框切換預覽操作區的模式。

```tsx file="../../_demos/file-browser-basic.tsx" preview

```

示例使用固定資料，不訪問網路。在搜尋框輸入 `profile` 檢視搜尋結果，輸入 `error` 檢視搜尋失敗；點選「匯入資源」，底部會顯示宿主收到的 `onImportResources` 事件。

### ACL 許可權管理

開啟 `acl` 後，`viking://resources/` 下的節點顯示當前使用者的有效許可權，許可權為「可管理」時可以在許可權標籤的詳情裡開啟授權彈窗。切換「當前許可權」檢視不同許可權下的介面，勾選「模擬儲存失敗」或「模擬成員載入失敗」檢視失敗狀態。

```tsx file="../../_demos/file-browser-acl.tsx" preview

```

示例是離線模擬，不會修改真實授權。

### 預覽操作區

`previewActions` 隱藏內建操作，`previewSlots` 追加、替換或隱藏操作區；基礎用法示例底部的下拉框可以檢視各種模式。

```tsx
<FileBrowser
  previewActions={{
    edit: false,
    delete: false,
    importPack: false,
    configure: false,
  }}
  previewSlots={{
    actionItems: (context) => [
      ...context.defaultActions,
      [
        {
          key: 'share',
          icon: <ShareIcon />,
          label: '分享',
          onClick: () => share(context.path),
        },
      ],
    ],
  }}
/>
```

### FileBrowserPreviewActions

每一項預設在當前資源支援該操作時顯示。設為 `false` 隱藏，設為 `true` 不會增加資源本來沒有的能力。

| 引數        | 說明                                                                                                                                          | 型別      | 預設值 |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------- | ------ |
| copyPath    | 「複製路徑」按鈕，位於麵包屑旁；預覽有路徑時顯示                                                                                              | `boolean` | `true` |
| viewSwitch  | 「預覽 / 原始碼」切換；只在同時支援兩種檢視的格式上顯示，圖片、影片和 `viking://system` 下的目錄不支援                                        | `boolean` | `true` |
| edit        | 編輯按鈕；只在可寫且格式可編輯的檔案上顯示，經驗檔案、`viking://system` 下的資源和 L0/L1 摘要不可編輯                                         | `boolean` | `true` |
| copyContent | 「複製內容」操作，複製當前預覽的文本或目錄摘要，超過預覽行數上限時只複製已顯示的部分；二進位制媒體和 `viking://system` 下的目錄不顯示         | `boolean` | `true` |
| download    | 「下載」操作，下載檔案的原始內容；只在檔案上顯示                                                                                              | `boolean` | `true` |
| history     | 「檢視歷史版本」操作；在支援的文本檔案和 Wiki 目錄上顯示                                                                                      | `boolean` | `true` |
| configure   | 「編譯配置」操作；只在 Wiki 編譯目標的根目錄上顯示，只讀時仍可檢視                                                                            | `boolean` | `true` |
| importPack  | 「匯入 .ovpack」操作；只在可寫的目錄上顯示，且目錄位於 `viking://user`（含 `viking://~`）或 `viking://resources` 下                           | `boolean` | `true` |
| exportPack  | 「匯出 .ovpack」操作；在 `viking://user`（含 `viking://~`）或 `viking://resources` 下的檔案和目錄上顯示，`.relations.json` 等內部控制檔案除外 | `boolean` | `true` |
| delete      | 「刪除文件」操作；只在可管理的檔案上顯示，目錄、`viking://system` 下的檔案和 L0/L1 摘要不可刪除                                               | `boolean` | `true` |

### FileBrowserPreviewSlots

| 引數         | 說明                                                                                                | 型別                                                                                               | 預設值 |
| ------------ | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------ |
| actions      | 替換整個操作區，`null` 隱藏；替換後需要自己渲染儲存、取消和追加的操作，複製路徑和許可權標籤不受影響 | `ReactNode \| ((context: FileBrowserPreviewActionContext) => ReactNode)`                           | -      |
| extraActions | 追加到預設操作區末尾，編輯狀態下隱藏                                                                | `ReactNode`                                                                                        | -      |
| actionItems  | 替換預設的操作列表；函式形式可以通過 `context.defaultActions` 複用、追加或重排預設操作              | `FilePreviewActionItems \| ((context: FileBrowserPreviewActionContext) => FilePreviewActionItems)` | -      |

操作列表的每一項是單個操作或一組操作（陣列），格式見 [FilePreview](../components/file-preview)。

### FileBrowserPreviewActionContext

`previewSlots.actions` 和 `previewSlots.actionItems` 的函式形式收到的上下文，只讀取，不需要自己構造。它包含 [FilePreview](../components/file-preview) 的 `FilePreviewActions` 的全部屬性（`source`、`path`、`viewMode`、`setViewMode`、`canSwitchView`、`editing`、`busy`、`canEdit`、`startEditing`、`saveEditing`、`cancelEditing`、`canCopyPath`、`copyPath`），並增加下面三項。

| 引數           | 說明                                                                  | 型別                     | 預設值 |
| -------------- | --------------------------------------------------------------------- | ------------------------ | ------ |
| defaultActions | 內建操作，已按資源能力、`previewActions`、`readOnly` 和許可權過濾     | `FilePreviewActionItems` | -      |
| canDelete      | 當前使用者能否刪除當前資源，不受 `previewActions.delete` 影響         | `boolean`                | -      |
| deleteFile     | 開啟內建的刪除確認框，不會關閉預覽頁籤；`canDelete` 為 `false` 時無效 | `() => void`             | -      |

`defaultActions` 分三組：複製內容、下載、歷史版本和編譯配置；匯入和匯出 .ovpack；刪除。各操作的 `key` 依次是 `copyContent`、`download`、`history`、`configure`、`importPack`、`exportPack`、`delete`。

### FileBrowserAclOptions

`acl` 傳入物件時的配置，全部可選；傳入 `true` 等同於不設定任何選項。

| 引數              | 說明                                                                                                               | 型別                                                                                                                                          | 預設值   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| readOnly          | 禁止修改授權，仍可檢視                                                                                             | `boolean`                                                                                                                                     | `false`  |
| resolvePermission | 返回當前使用者在資源上的有效許可權，未知時返回 `undefined`；省略時讀取 `fs/stat` 的 `access`，缺失時探測管理許可權 | `(uri: string, context: FileBrowserAclContext) => Promise<FileBrowserAclLevel \| undefined>`                                                  | 內建實現 |
| listPrincipals    | 返回可新增的 User 或 Group，`page` 從 1 開始；省略時呼叫帳號的使用者和使用者組介面，不讀取憑證                     | `(query: { type: 'user' \| 'group'; keyword: string; page: number }, context: FileBrowserAclContext) => Promise<FileBrowserAclPrincipalPage>` | 內建實現 |
| onChange          | 授權儲存成功後觸發，儲存失敗時不觸發；回撥丟擲的錯誤不影響儲存結果                                                 | `(report: FileBrowserAclReport) => void`                                                                                                      | -        |

### FileBrowserAclContext

`resolvePermission` 和 `listPrincipals` 的第二個引數，只讀取，不需要自己構造。

| 引數           | 說明                                                            | 型別               | 預設值 |
| -------------- | --------------------------------------------------------------- | ------------------ | ------ |
| client         | 當前 Provider 的請求客戶端                                      | `OvClient`         | -      |
| requestOptions | 本次請求使用的配置，呼叫 `client.request` 時作為 `options` 傳入 | `OvRequestOptions` | -      |

### FileBrowserAclPrincipalPage

| 引數       | 說明                                             | 型別       | 預設值 |
| ---------- | ------------------------------------------------ | ---------- | ------ |
| principals | 當前頁的成員，格式為 `user:<id>` 或 `group:<id>` | `string[]` | 必填   |
| hasMore    | 是否還有下一頁                                   | `boolean`  | 必填   |

### FileBrowserAclReport

`acl.onChange` 收到的授權報告，只讀取，不需要自己構造。`acl_mode` 為 `'none'` 表示該節點及其上級都沒有設定許可權，`'inherit'` 表示繼承上級併疊加直接授權，`'restricted'` 表示不繼承上級、只按直接授權生效。

| 引數              | 說明                 | 型別                                  | 預設值 |
| ----------------- | -------------------- | ------------------------------------- | ------ |
| uri               | 資源 URI             | `string`                              | -      |
| acl_mode          | 許可權模式           | `'none' \| 'inherit' \| 'restricted'` | -      |
| direct_entries    | 直接授予該資源的授權 | `FileBrowserAclEntry[]`               | -      |
| inherited_entries | 從上級繼承的授權     | `FileBrowserAclEntry[]`               | -      |
| effective_entries | 實際生效的授權       | `FileBrowserAclEntry[]`               | -      |

### FileBrowserAclEntry

授權報告裡的一條授權，只讀取，不需要自己構造。

| 引數      | 說明                                                                      | 型別                  | 預設值 |
| --------- | ------------------------------------------------------------------------- | --------------------- | ------ |
| principal | 被授權的成員，格式為 `user:<id>` 或 `group:<id>`，`user:*` 表示全部使用者 | `string`              | -      |
| level     | 授權級別                                                                  | `FileBrowserAclLevel` | -      |

### FileBrowserAclLevel

`'read' | 'write' | 'manage'`：`read` 可以檢視內容，`write` 可以檢視和編輯，`manage` 還可以刪除並管理授權。

| pendingConflicts | Wiki：是否有待處理的衝突，未知時為 `undefined`  | `boolean`                | -      |

## 注意

### 請求與佈局

- FileBrowser 的高度是父容器的 100%，父容器需要有明確的高度；元件沒有外框和背景，由宿主決定。
- `rootUri`、`defaultExpandedUri` 或 `requestOptions` 變化時，目錄樹回到根目錄並重新載入，進行中的請求被中止；`requestOptions` 變化還會讓預覽重新請求。
- 內聯的 `requestOptions` 物件在每次渲染時都是新的，請在元件外定義或用 `useMemo` 保持引用穩定。
- `acl.resolvePermission` 和 `acl.listPrincipals` 同理：引用變化會重新請求許可權和成員，請在元件外定義或用 `useCallback` 保持穩定。
- 型別從 `@openviking/react/modules/file-browser` 匯出，包根入口只匯出 `FileBrowser` 和 `FileBrowserProps`。

### 目錄與預覽

- 目錄按需展開，每頁載入 200 項，目錄末尾的「載入更多」繼續載入。
- 根目錄 `viking://` 下按使用者、會話、Agent、資源的順序顯示，其餘目錄隨後；`rootUri` 為其他值時保持介面返回的順序。
- 點選檔案預覽正文；點選目錄展開並選中它，預覽區顯示該目錄的 L0 摘要和 L1 總覽。
- `viking://system` 下的目錄保留頁籤和路徑，不顯示摘要；目錄中的檔案仍可預覽。
- 設定 `uri` 只切換預覽的資源，不會展開目錄樹；需要初始就展開到某個位置時使用 `defaultExpandedUri`。
- 文本檔案最多讀取 2000 行，超出時提示內容被截斷。
- 圖片、影片、音訊、PDF、Office 文件和壓縮包按副檔名通過內容下載介面讀取。
- 可編輯的格式有 `.md`、`.json`、`.jsonl`、`.txt`、`.yaml`、`.yml`：進入編輯時重新讀取完整內容，儲存呼叫 `POST /api/v1/content/write`，成功後重新載入預覽。
- 檔案正文讀取顯式請求 `raw=false`，並在區塊共用讀取層兜底；預覽、原始碼和編輯草稿使用同一份正文。
- 記憶名稱空間內檔案末尾的 `MEMORY_FIELDS` 註釋是服務端寫入的內部後設資料，預覽和編輯時都不顯示；正文中間的同形註釋，以及資源和技能文件裡的示例保留。
- YAML 檔案按標量範圍保留值中的同名註釋，獨立追加的真實尾註仍會移除；正文不經過重新序列化。
- 行邊界、空白與單詞字元沿用服務端的 Python 語義。讀滿預覽上限時先取全文、過濾後再截斷，避免把首屏末尾誤當成檔案末尾，或展示被截斷的元資訊。
- Wiki 歸屬沿用編譯目標和資源標籤判斷，與看板頁籤是否顯示無關。末尾的 `CONFLICTS_CONTENT` 註釋從正文分離，仍提供給衝突看板解析；損壞的 JSON 不進入正文，看板保留錯誤與重試。
- 編輯儲存 Wiki 檔案時通過原生 `resolve_conflicts: true` 契約交由服務端保留、更新衝突記錄；其他文本檔案不攜帶此引數。
- 所有 YAML 頭、普通 HTML 註釋和 Markdown 程式碼圍欄中的示例保留；已確認作用域的 Markdown 檔案中，獨佔一行的未閉合保留尾註隱藏至檔案末尾；YAML 頭、程式碼圍欄和行內示例中的標記保留。
- 重新整理按鈕重新載入已展開的目錄和當前預覽。

### 開啟並定位資源

`FileBrowser` 支援 React 18/19 的 ref。匯入結果、搜尋結果或檔案連結可呼叫 `openResource`：模組開啟預覽，逐級展開祖先目錄，按需載入後續頁找到目標，選中並滾動到該行。其他分支的展開狀態保留；重複開啟同一 URI 也會再次滾動定位。

```tsx
import { useRef } from 'react';
import { FileBrowser } from '@openviking/react/modules/file-browser';
import type { FileBrowserHandle } from '@openviking/react/modules/file-browser';

const browserRef = useRef<FileBrowserHandle>(null);

<FileBrowser ref={browserRef} />;

await browserRef.current?.openResource(resultUri, { reveal: true });
```

傳入以 `/.abstract.md` 或 `/.overview.md` 結尾的連結時，模組開啟父目錄並分別切換到 L0 摘要或 L1 總覽；樹定位與 `onUriChange` 使用父目錄 URI。同一目錄內重複開啟連結也會切換到指定層級，之後仍可手動切換。

`reveal` 預設 `true`；傳 `{ reveal: false }` 只發出開啟預覽的請求，發出後返回 `true`。普通 `uri` 屬性變化不會展開或滾動目錄樹。受控模式需要宿主在 `onUriChange` 中更新 `uri` 接受開啟意圖。目標行選中並滾動後 Promise 返回 `true`；目標不存在、不可訪問、不在 `rootUri` 下、被後續操作替代或元件解除安裝時返回 `false`。根目錄本身沒有樹行，開啟其預覽後返回 `false`。目錄列表請求或必要的當前使用者別名解析失敗會 reject，宿主可捕獲並展示提示。服務端明確不支援別名解析時，按原 URI 寫法匹配。呼叫方主動取消時返回 `false`。Promise 不等待預覽正文載入完成。內建搜尋複用同一導航入口。

### 搜尋

- 左欄頂部的搜尋框開啟模組內建的搜尋彈窗；`⌘K` 是真實快捷鍵，同一頁面掛多個例項時只有最近互動過的那個響應。
- 輸入停頓 400ms 後自動請求，沒有提交按鈕。關閉彈窗會取消在途請求並清空輸入與篩選。
- 四種檢索方式共用一套輸入與結果列表。有匹配結果時，可在結果區頂部點「切換」：

| 方式     | 介面                    | 輸入解釋   | 可用篩選                     |
| -------- | ----------------------- | ---------- | ---------------------------- |
| `find`   | `/api/v1/search/find`   | 自然語言   | 目錄（多選）、內容層級、時間 |
| `search` | `/api/v1/search/search` | 自然語言   | 同上                         |
| `grep`   | `/api/v1/search/grep`   | 正規表示式 | 目錄（單選）、忽略大小寫     |
| `glob`   | `/api/v1/search/glob`   | 檔案模式   | 目錄（單選）                 |

- 結果按 URI 去重；`grep` 例外——同一檔案的多行命中是不同結果，各帶自己的行號。
- `glob` 的模式不含 `/` 時自動補 `**/` 字首；目錄命中去掉尾斜槓後再參與導航，目錄這一事實記在 `isDir` 上。
- 高階面板的篩選項按當前方式啟用或停用，停用的分割槽保留可見並置灰，標題旁說明原因。目錄候選從 `rootUri` 派生，使用者根用 `~` 別名；切換根時失效的已選目錄會被丟棄。
- 進階選項可勾選常用目錄，或通過「選擇目錄」繼續瀏覽子目錄。選擇建立時間或更新時間後顯示日期範圍；忽略大小寫只在 `grep` 中顯示。
- 按 **↑ / ↓** 切換當前結果，點選或按 **Enter** 關閉彈窗、開啟資源並在樹中定位。

### 預覽操作區

- 標題行右側依次是「預覽 / 原始碼」切換、編輯按鈕和操作選單，「複製路徑」在麵包屑旁，許可權標籤在其後。
- 顯隱開關只控制預設按鈕是否顯示，不改變能力：`previewSlots` 上下文裡的 `canDelete`、`deleteFile()` 和編輯方法仍然可用。
- `readOnly` 禁止所有寫入，包括儲存編譯配置；開啟 `acl` 後，編輯、匯入和儲存編譯配置要求 `write` 或 `manage`，刪除要求 `manage`。
- 複製內容、下載、匯出、歷史版本和檢視編譯配置不受 `readOnly` 和 ACL 的限制。
- 沒有開啟 `acl`，或資源不在 `viking://resources/` 下時，區塊不探測許可權，由服務端鑑權。
- 儲存普通檔案時會彈出版本備註。確認後，FileBrowser 先儲存正文，再為當前檔案建立快照。若未建立快照，正文仍保留，預覽會顯示提示。Wiki 檔案直接儲存。
- 歷史版本：`GET /api/v1/snapshot/log` 讀取該資源最近最多 500 條快照；Wiki 編譯產物用 `GET /api/v1/snapshot/versions` 讀取最多 100 個保留版本。可預覽或複製歷史正文，並與當前檔案對比。歷史彈窗為只讀。
- 編譯配置：`GET /api/v1/compile/config` 讀取，`POST /api/v1/compile/config/update` 儲存來源目錄、技能、指令、自動更新和每天或每週的定時更新。
- 匯入 .ovpack：先通過 `POST /api/v1/resources/temp_upload` 上傳檔案，再呼叫 `POST /api/v1/pack/import` 匯入到當前目錄；失敗時保留所選檔案，重試會重新上傳。
- 匯出 .ovpack：呼叫 `POST /api/v1/pack/export`，把返回的內容儲存為 `<名稱>.ovpack`；下載使用 `GET /api/v1/content/download`。
- 刪除：確認後呼叫 `DELETE /api/v1/fs?uri=...&wait=true`；失敗時保留確認框並允許重試，成功後選中父目錄並重新整理目錄樹。只能刪除檔案，不能刪除目錄。
- 操作進行中不會重複提交，切換帳號或資源、解除安裝元件時會中止進行中的請求。

### 許可權（ACL）

- `acl` 只作用於 `viking://resources/` 下的非根節點；其他位置不顯示許可權標籤，也不受 ACL 限制。
- 有效許可權先讀 `GET /api/v1/fs/stat` 返回的 `access`；沒有該欄位時呼叫 `GET /api/v1/acl` 探測，成功視為 `manage`，403 視為未知。
- 許可權未知時不顯示許可權標籤，編輯和刪除不可用；許可權讀取失敗時標題旁顯示「重試」。
- 許可權標籤顯示有效許可權，`manage` 的標籤詳情裡有「管理許可權」按鈕，點選開啟授權彈窗。
- `read` 不能編輯，`write` 可以編輯和匯入，`manage` 還可以刪除和管理授權。
- 彈窗裡可以搜尋並新增 User 或 Group，授予 `read`、`write` 或 `manage`，也可以調整級別和移除；「資料空間管理員」一行固定為 `manage`。
- 節點繼承上級許可權時，只增加許可權會直接儲存；降低或移除已有許可權需要先在彈窗裡確認停止繼承，節點隨後變為受限（`restricted`），取消則不寫入。
- 受限節點可以「恢復繼承」：彈窗先列出將不再生效的直接授權，確認後清空直接授權並跟隨上級。
- 儲存期間不能重複提交或關閉彈窗；儲存失敗時保留上次成功的授權並顯示服務端的原因。
- 儲存成功後重新整理目錄和預覽；服務端的索引更新可能非同步完成，以服務端的鑑權結果為準。
- 目錄列表（`fs/ls`）裡 `access: 'denied'` 的節點不能選中或展開，`access: 'container'` 的節點只能展開以訪問有許可權的子節點、不能預覽自身。
- `access: 'read'` 的節點顯示只讀標記。
- 以上節點標記來自目錄列表，不依賴 `acl`。
- 授權呼叫 `GET`、`PUT`、`DELETE /api/v1/acl`；成員目錄呼叫帳號的使用者和使用者組介面（使用者每頁 20 條，`include_credentials=false`），需要在 Provider 或 `requestOptions` 裡提供 `accountId`。
- 使用者組目錄需要帳號管理許可權，資源管理者無權讀取時會顯示失敗和重試，可以用 `acl.listPrincipals` 接入自己的目錄。
- `acl.readOnly` 只禁止修改授權，與 `readOnly` 相互獨立。

### 看板

- 使用者的 `memories/experiences` 目錄和其中直接的 `.md` 檔案（包括 `peers/<peer>/` 下的）顯示經驗看板。
- 帶有 `compile_target=true` 標籤或屬於編譯配置的目錄顯示 Wiki 看板，目錄下的檔案和子目錄也有各自的 Wiki 看板。
- 標籤優先於編譯配置：配置裡缺少該目標時仍顯示看板。
- 編譯配置（`GET /api/v1/compile/configs`）按需讀取：開啟 Wiki 看板，或正文中的 Wiki 保留尾註需要確認歸屬時才請求，普通瀏覽不請求。
- `dashboardKinds` 不含 `'wiki'` 時，不再識別 Wiki，也不讀取編譯配置，Wiki 資源不再提供編譯配置和編譯版本索引。
- 檔案樹裡帶看板的行顯示看板圖示，點選直接開啟；Wiki 有待處理衝突時圖示不同。
- 預覽區的頁籤可以在正文和看板之間切換。
- 普通資源沒有 Wiki 頁籤，已識別的 Wiki 即使沒有衝突也保留看板。
- `viking://~/...` 別名和規範 URI 指向同一個資源時識別結果相同，傳給 `renderDashboard` 的 `uri` 保持原來的寫法。
- 兩個看板也可以脫離 FileBrowser 單獨使用，見 [WikiDashboard](../components/wiki-dashboard) 和 [ExperienceDashboard](../components/experience-dashboard)。

### 失敗狀態

- 目錄列表失敗時，樹裡顯示失敗行和重試按鈕，根目錄失敗也一樣，不會顯示成「沒有檔案」；失敗行的「重試」只重新載入該目錄。
- 預覽失敗時，右側顯示失敗狀態：`labels.error` 是結論，服務端返回的原始訊息是原因，`labels.retry` 是重試按鈕，重試會同時重新載入目錄樹和當前預覽。
- 只有沒選中資源時才顯示空狀態（`labels.empty`），選中了資源卻讀不出來時顯示失敗狀態。
- 目錄的 L0 摘要和 L1 總覽分別請求：一級失敗時只有該級顯示失敗原因，兩級都失敗時整個預覽顯示失敗狀態；服務端沒有返回訊息時顯示 `labels.summaryFailed`。
- 搜尋失敗時，彈窗保留介面返回的原因，可以再次提交同一個關鍵詞重試。

### 目錄樹寬度

- 容器小於 521px 時，目錄樹和預覽上下排列，隱藏橫向分隔條。

- 樹與預覽之間有可拖拽的分隔條：拖動，或聚焦後用左右方向鍵（每次 16px）調整樹寬；分隔條的無障礙名稱來自 `labels.resizeTree`。
- 預設 352px，最小 200px，最大為 520px 與「容器寬度減去 321px」（預覽區至少 320px，加 1px 分隔線）中的較小值，因此放進窄欄時樹會收窄，不會擠沒預覽區。
- 寬度只在當前例項內生效，不寫入 `localStorage`，是否記住由宿主決定。
- 當前寬度以 CSS 變數 `--ov-file-browser-tree-width` 寫在根元素的內聯樣式上，可以讀取，但覆蓋它不會生效。
