# 區塊

區塊自帶資料載入和狀態管理，從 `@openviking/react` 匯入後放進頁面，就能得到一塊完整的功能：檔案瀏覽、命令面板或級聯選擇。

## 何時使用

- 想直接得到檔案瀏覽或命令面板，由區塊負責請求、分頁和狀態時：FileBrowser 和 Console 通過 `OpenVikingProvider` 請求 OpenViking 原生 API。
- 需要依次選擇知識庫、資料空間和使用者時：ScopeCascade 通過你提供的三個載入函式取數，不請求 OpenViking 原生 API。
- 只需要純檢視、資料由自己載入時，使用[業務元件](../components/)，它們不需要 `OpenVikingProvider`。

| [FileBrowser 檔案瀏覽](./file-browser)   | 目錄樹、搜尋和檔案預覽組成的檔案瀏覽區塊：讀取 OpenViking 的目錄和內容，支援預覽、編輯、匯入匯出、歷史版本和許可權管理，並內建 Wiki 與經驗看板。 | `@openviking/react/modules/file-browser`  | 需要 `OpenVikingProvider`，支援 `requestOptions`   |

## 無頭模組

[VikingBot](./viking-bot) 提供 `useVikingBotChat`、`useVikingBotSessions` 及契約，從 `@openviking/react/modules/viking-bot` 引入。Console 內部複用同一模組；獨立宿主可以把狀態接入 VikingBot 或自己的檢視。此入口不匯出元件或 CSS，Hook 不從包根或 Console 轉匯出。

## 引入

```tsx
import { FileBrowser } from '@openviking/react/modules/file-browser';
import '@openviking/react/modules/file-browser/style.css';
```

區塊的子路徑是 `modules`：從 `@openviking/react/modules/<名稱>` 匯入，完整路徑見上表。根入口 `@openviking/react` 也匯出區塊本體和主 Props 型別，例如 `FileBrowser` 和 `FileBrowserProps`；Labels、Slots 和列舉等其他型別只從子路徑匯入。沒有 `@openviking/react/modules` 這樣的聚合入口。

JavaScript 匯入不會載入 CSS，從下面選一個樣式入口，每個入口都可以單獨使用：

- `@openviking/react/modules/<名稱>/style.css`：單個區塊，已包含它用到的元件的樣式。
- `@openviking/react/modules/style.css`：全部區塊。
- `@openviking/react/style.css`：整個元件庫。

## 請求配置

FileBrowser 和 Console 通過最近的 `OpenVikingProvider` 請求 OpenViking 原生 API，必須放在 Provider 內。在應用根部放一個 Provider，服務地址和憑證只配置這一次，區塊本身不接收這些 props：

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { FileBrowser } from '@openviking/react/modules/file-browser';
import { Console } from '@openviking/react/modules/console';
import '@openviking/react/modules/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <FileBrowser />
  <Console />
</OpenVikingProvider>;
```

沒有 Provider 時，FileBrowser 不發起請求，目錄樹一直停在載入狀態；Console 使用不帶身份資訊的同源預設 Client。

ScopeCascade 不走共享 Client，沒有 `requestOptions`，也不需要 Provider；放在 Provider 內時，它只繼承 Provider 的 `locale`。

### OpenVikingProvider

欄位省略時繼承外層 Provider，最外層省略時使用「預設值」一列。

| 引數        | 說明                                                                                                 | 型別                                          | 預設值                   |
| ----------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------- | ------------------------ |
| baseURL     | 服務地址及可選的閘道器字首，不含 `/api/v1`，空字串表示同源請求                                       | `string`                                      | `''`                     |
| apiKey      | 憑證，作為 `X-API-Key` 請求頭髮送；商業版由瀏覽器 Cookie 鑑權，不需要傳入                            | `string \| (() => string \| Promise<string>)` | -                        |
| accountId   | OpenViking 帳號 ID，對應資料空間，作為 `X-OpenViking-Account` 請求頭髮送                             | `string \| (() => string \| Promise<string>)` | -                        |
| userId      | 帳號內的使用者 ID，作為 `X-OpenViking-User` 請求頭髮送                                                 | `string \| (() => string \| Promise<string>)` | -                        |
| resourceId  | 當前庫 ID，決定請求落在哪個庫，作為 `V-Resource-Id` 請求頭髮送                                       | `string \| (() => string \| Promise<string>)` | -                        |
| credentials | 傳給 `fetch` 的 `credentials`，決定是否攜帶 Cookie；跨源請求仍遵循服務端 CORS 和瀏覽器的 Cookie 策略 | `'include' \| 'same-origin' \| 'omit'`        | `'include'`              |
| signal      | 中止請求的訊號，觸發後進行中的請求被取消                                                             | `AbortSignal`                                 | -                        |
| fetch       | 替換全域 `fetch`，用於測試、鏈路追蹤或沒有全域 `fetch` 的環境                                        | `typeof fetch`                                | 全域 `fetch`             |
| locale      | 子樹的介面語言，規則見[國際化](../guide/i18n)                                                        | `'zh-CN' \| 'en-US'`                          | 繼承上級，預設 `'en-US'` |
| children    | 使用這套請求配置的子樹                                                                               | `ReactNode`                                   | -                        |

- 身份欄位 `apiKey`、`accountId`、`userId` 和 `resourceId` 也可以傳函式，每次請求重新求值，因此能讀到輪換後的憑證。
- `fetch`、`signal` 和函式形式的身份欄位按引用比較，變化會建立新的 Client，使用它的區塊隨之重置，請保持它們的引用穩定。
- Provider 掛載時不發請求，也不讀取瀏覽器裡儲存的憑證。

### 覆蓋請求配置

FileBrowser 和 Console 有可選的 `requestOptions` 屬性，型別是 `@openviking/react/client` 匯出的 `OvRequestOptions`，用來只改這一個區塊的請求配置，例如讓它訪問另一個庫：

```tsx
const otherLibrary = { resourceId: 'library-b' };

<FileBrowser requestOptions={otherLibrary} />;
```

`OvRequestOptions` 包含 `baseURL`、`apiKey`、`accountId`、`userId`、`resourceId` 和 `signal`，含義與上表相同；`credentials` 和 `fetch` 只能在 Provider 上設定。覆蓋規則如下：

- 逐欄位解析，優先順序從高到低：區塊的 `requestOptions`、最近的 `OpenVikingProvider`、庫預設值。
- 巢狀 Provider 時，內層只覆蓋自己宣告的欄位，其餘繼承外層。
- 欄位省略或為 `undefined` 表示繼承；`baseURL` 傳 `''` 則明確表示同源。
- 身份欄位傳 `''` 清除繼承到的值，請求不再發送對應請求頭。
- 覆蓋只作用於這一個區塊，不修改 Provider，也不影響其他區塊。
- `requestOptions` 物件要保持引用穩定，在元件外定義或用 `useMemo`；各區塊在它變化後的行為見各自頁面的「注意」。
