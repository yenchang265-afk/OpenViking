# 登入與認證表單

六個元件，覆蓋選擇登入方式、郵箱或 API Key 登入、請求重置郵件、設定密碼和確認邀請。

## 何時使用

- `EmailLoginForm`：用郵箱和密碼登入，可附帶忘記密碼入口。
- `ApiKeyLoginForm`：用 API Key 登入，輸入內容預設遮蔽，可切換顯示。
- `PasswordResetRequestForm`：使用者忘記密碼時請求傳送重置郵件，支援重新發送並顯示等待秒數。
- `PasswordSetupForm`：首次設定密碼，或通過郵件連結重置密碼。
- `LoginMethodSelector`：宿主支援多種登入方式時，讓使用者先選擇一種。
- `InvitationConfirmation`：展示邀請資訊，讓使用者接受、拒絕或稍後處理。
- 請求、登入態和頁面跳轉由宿主負責：這些元件只負責輸入、校驗和展示，不發起請求，也不需要 `OpenVikingProvider`。

## 引入

```tsx
import { EmailLoginForm } from '@openviking/react/components/auth/email-login-form';
import '@openviking/react/components/auth/email-login-form/style.css';

import { ApiKeyLoginForm } from '@openviking/react/components/auth/api-key-login-form';
import '@openviking/react/components/auth/api-key-login-form/style.css';

import { PasswordResetRequestForm } from '@openviking/react/components/auth/password-reset-request-form';
import '@openviking/react/components/auth/password-reset-request-form/style.css';

import { PasswordSetupForm } from '@openviking/react/components/auth/password-setup-form';
```

## API

### 公共屬性

`EmailLoginForm`、`ApiKeyLoginForm`、`PasswordResetRequestForm` 和 `PasswordSetupForm` 都支援以下屬性。

| 引數        | 說明                                                                   | 型別                  | 預設值                   |
| ----------- | ---------------------------------------------------------------------- | --------------------- | ------------------------ |
| loading     | 宿主處理提交期間設定：停用輸入和提交，並顯示忙碌狀態                   | `boolean`             | `false`                  |
| disabled    | 停用輸入和提交                                                         | `boolean`             | `false`                  |
| error       | 顯示在提交按鈕上方的錯誤提示，元件不解析後端錯誤碼                     | `ReactNode`           | -                        |
| title       | 表單標題，渲染為 `h2`                                                  | `ReactNode`           | -                        |
| description | 標題下方的說明                                                         | `ReactNode`           | -                        |
| back        | 表單頂部的返回入口，沒有 `onClick` 時不顯示                            | `AuthAction`          | -                        |
| agreements  | 協議配置；`items` 非空時顯示協議勾選框，未勾選的提交會先彈出確認對話方塊 | `AuthAgreements`      | -                        |
| labels      | 覆蓋介面文案，欄位見 `AuthLabels`                                      | `Partial<AuthLabels>` | -                        |
| locale      | 介面語言，規則見[國際化](../guide/i18n)                                | `'zh-CN' \| 'en-US'`  | 繼承上級，預設 `'en-US'` |
| className   | 附加到根元素的類名                                                     | `string`              | -                        |

## 注意

- 提交時先校驗輸入，再處理協議：已勾選則直接觸發 `onSubmit`，未勾選則彈出確認對話方塊，點選同意會勾選協議並觸發 `onSubmit`。
- 確認對話方塊使用原生 `<dialog>` 的 `showModal()`，需要瀏覽器支援。取消或按 Esc 會關閉對話方塊，保留輸入，不勾選協議，也不提交。
- 元件不發起請求，也忽略 `onSubmit` 的返回值。宿主在處理期間設定 `loading`，失敗時通過 `error` 展示，成功後的跳轉也由宿主完成。
- 表單的 `loading` 和 `disabled` 停用輸入、提交按鈕和 `forgotPassword`，`back` 和 `alternateLogin` 仍可點選；`InvitationConfirmation` 的 `loading` 和 `disabled` 停用全部按鈕。
- 輸入內容、欄位錯誤、密碼顯隱和協議勾選儲存在表單內部。更換帳號或協議內容時，給表單設定新的 `key` 重新掛載，才會清空輸入和已同意的協議。
- 郵箱按基本格式校驗，為空時同樣提示郵箱無效。登入密碼和 API Key 只檢查非空，不套用新密碼的強度規則。
- `PasswordSetupForm` 檢查兩次輸入一致，密碼強度只由 `validatePassword` 決定，元件沒有預設強度規則。
- 把 `required`、`invalidEmail` 或 `mismatch` 設為空字串，只會隱藏對應的錯誤文案，校驗結果不變。
- 密碼和 API Key 只儲存在輸入框狀態裡，元件不會儲存、記錄或去除首尾空白；郵箱在提交前去除首尾空白。
- 輸入框設定了 `autocomplete`，密碼管理器可以識別：郵箱登入用 `username` 和 `current-password`，設定密碼用 `new-password`，API Key 輸入框為 `off`。
- `LoginMethodSelector` 沒有內建文案，不提供 `locale` 和 `labels`。`InvitationConfirmation` 只有接受按鈕一條內建文案，用 `acceptLabel` 修改，不提供 `labels`。
- `InvitationConfirmation` 只展示 `details`，`onAccept`、`decline` 和 `defer` 只通知宿主。邀請預覽、狀態判斷，以及展示登入、設定密碼還是確認加入，由宿主決定。
- 每個元件最寬 440px，寬度隨容器收縮，居中和整頁佈局由宿主決定。
- 六個元件共用同一份樣式，各 `style.css` 入口內容相同；同一頁面用到多個元件時，引入其中一個即可。
- 顏色取自 `--ov-ui-color-*` 主題變數，暗色模式跟隨 `<html>` 上的 `.dark` 類，詳見[快速開始](../guide/getting-started)。
- 型別從各元件子路徑匯出：`AuthAction`、`AuthAgreements` 和 `AuthLabels` 可從四個表單的子路徑匯入，`AuthAction` 也可從 `invitation-confirmation` 匯入。包根入口只匯出六個元件和它們的 Props 型別。
