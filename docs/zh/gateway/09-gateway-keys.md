# 管理閘道器金鑰

本頁面向需要簽發閘道器金鑰的人：給自己簽發的普通使用者，以及替他人簽發金鑰、或為某位使用者做清理的帳號管理員。讀完後你能簽發金鑰並填進客戶端，也清楚金鑰被吊銷、或其使用者的 OpenViking API 金鑰變化後會發生什麼。開始前至少需要一個[上游](07-upstreams.md#upstreams)和一份[上下文配置](08-context-profiles.md#context-profiles)。

## 什麼是閘道器金鑰 {#gateway-keys}

在 Studio 中：**OpenViking 閘道器** → **金鑰**。閘道器金鑰（`ovgw_…`）是客戶端用來代替服務商 API Key 的憑證。每把金鑰繫結：

- **一位 OpenViking 使用者。** 閘道器以這位使用者的身份、用其本人的 [OpenViking API 金鑰](../guides/22-gateway-operations.md#keys-and-credentials)召回和儲存記憶，所以金鑰的許可權永遠不會超出使用者本人，見[按使用者隔離](11-security-and-data.md#isolation-by-user)。
- **一份上下文配置**，決定用這把金鑰的對話如何召回和儲存記憶。
- **一組上游**，還可以進一步限定允許使用的模型。

**金鑰**標籤頁列出你自己的金鑰；帳號管理員和 root 能看到本帳號的全部金鑰，並多出一列 **OpenViking 使用者**。**金鑰**列只顯示每把金鑰的開頭幾個字元。

## 簽發金鑰 {#issue-a-key}

如果**金鑰**標籤頁提示先新增上游或建立上下文配置，請先完成；自己沒有許可權時，聯絡部署閘道器的人。在全新的閘道器上，概覽頁**快速模式**卡片裡的**一鍵生成金鑰**可以一步完成這些準備並簽發金鑰，見[快速開始清單和快速模式](06-manage-in-studio.md#get-started-checklist)。

1. 在**金鑰**標籤頁點**簽發金鑰**，彈出**簽發閘道器金鑰**對話方塊。
2. 填寫**名稱**，用來區分不同的金鑰，寫上使用者和客戶端最清楚，例如“Alice · Claude Code”。
3. 在**給誰用**裡選擇這把金鑰讀寫誰的記憶，見[金鑰給誰用](#who-the-key-is-for)。
4. 選擇一份**上下文配置**，並至少勾選一個**上游**。金鑰只能訪問選中的上游；每個請求到達時，閘道器從中挑一個協議與客戶端一致、並且提供所請求模型的上游（見[路由](07-upstreams.md#routing)）。
5. 按需填寫**允許的模型**，見[限定金鑰可用的模型](#allowed-models)。
6. 點**簽發金鑰**。閘道器會先向 OpenViking 核實這位使用者的 OpenViking API 金鑰，成功後會彈出**複製閘道器金鑰**對話方塊。如果看到的是**無法簽發金鑰**，見[簽發金鑰失敗](12-troubleshooting.md#issuing-a-key-fails)。
7. 點**複製閘道器金鑰**，再複製 Claude Code、Codex CLI 或聊天客戶端的配置，裡面已經填好真實金鑰和閘道器地址。某個客戶端的配置頁提示這把金鑰沒有已啟用的對應協議上游時，該客戶端用不了這把金鑰。複製完點**我已複製**。

金鑰簽發後立即可用。**複製閘道器金鑰**對話方塊是唯一一次能看到完整金鑰的機會：閘道器只儲存它的雜湊和開頭幾個字元。金鑰丟了就重新簽發。其他客戶端的接入方式見[把客戶端接入 OpenViking 閘道器](03-connect-clients.md#connect-clients)。

### 金鑰給誰用 {#who-the-key-is-for}

閘道器會以**給誰用**中所選使用者的身份召回和儲存記憶。能選哪些使用者取決於你的身份：

| 你的身份 | 能給誰簽發 |
| --- | --- |
| 普通使用者 | 只能給自己。Studio 顯示“以你的身份（<使用者>）讀寫記憶。”，不需要貼上任何金鑰。 |
| 帳號管理員 | 本帳號中的任意使用者或管理員。 |
| root | 先在側邊欄切換到目標帳號，再選擇該帳號中的使用者。root API 金鑰不能繫結到閘道器金鑰。 |
| 本地 dev 模式下的任何人 | 金鑰以 `default` 使用者的身份讀寫記憶。 |

除 root 外，給自己簽發時都不需要貼上金鑰。給別人簽發時，閘道器要從 OpenViking 讀取那位使用者的 API 金鑰。OpenViking 只儲存金鑰雜湊時讀不出來：這位使用者旁會標註“服務端讀不到這個使用者的使用者 API 金鑰，請改為貼上”，並出現**貼上 <使用者> 的使用者 API 金鑰**輸入框，填入該使用者當前的金鑰即可。也可以點**貼上使用者 API 金鑰**直接填寫。使用者列表載入失敗時，Studio 改為要求填寫 **OpenViking API 金鑰**。

持有閘道器金鑰就能使用對應使用者的記憶，因此能替他人簽發金鑰，就等於能讀取本帳號所有使用者的記憶，見[訪問控制](11-security-and-data.md#access-control)。

### 限定金鑰可用的模型 {#allowed-models}

**允許的模型**預設留空，表示允許這把金鑰所綁[上游](07-upstreams.md#upstreams)提供的全部模型。要限制時，填入客戶端傳送的模型名稱，包括別名。之後這把金鑰的模型列表只顯示這些名稱，請求其他模型會在到達服務商之前被拒絕。設定了允許模型的金鑰還要求每個請求都寫明模型；具體報錯見[客戶端收到閘道器返回的錯誤](12-troubleshooting.md#clients-get-an-error-from-the-gateway)。

## 簽發之後 {#after-issuing}

[閘道器金鑰](#gateway-keys)一經簽發就不能再改，但它發起的對話屬於它的使用者。

- **金鑰不能編輯。** 要更換上下文配置、上游、允許的模型或使用者，就簽發新金鑰，再吊銷舊的。
- **對話屬於使用者，不屬於金鑰。** 客戶端傳送相同的會話 ID 時，同一使用者的新金鑰會接著原來的[對話](03-connect-clients.md#how-conversations-are-recognized)，換金鑰不會打斷對話。
- **吊銷**（在**金鑰**標籤頁點**吊銷**，再點**吊銷金鑰**確認）後，這把金鑰立即失效。使用者的對話狀態和日誌保留，直到被顯式刪除或過期。尚未儲存到 OpenViking 的內容（例如最新一條回覆），只有在用新金鑰繼續這段對話時才會儲存。

### 每人一把金鑰 {#one-key-per-person}

記憶屬於[閘道器金鑰](#gateway-keys)背後的 OpenViking 使用者，所以共用一把金鑰的人也共用這位使用者的記憶。請給每人簽發一把金鑰。想讓不同客戶端使用不同的上下文配置，或者想單獨吊銷某個客戶端，再按客戶端分開簽發。

### 使用者的 OpenViking API 金鑰變了 {#when-the-openviking-key-changes}

每把閘道器金鑰都依賴其使用者當前的 [OpenViking API 金鑰](../guides/22-gateway-operations.md#keys-and-credentials)。這個金鑰重新生成或使用者被刪除後，OpenViking 會拒絕閘道器儲存的舊金鑰。閘道器在隨後的請求中發現這一點（最多延遲約 30 秒），刪除繫結它的閘道器金鑰，對話狀態和日誌保留。請用當前的 OpenViking API 金鑰重新簽發。

如果 OpenViking 只是暫時連不上或返回錯誤，閘道器不會刪除金鑰，請求照常發給模型，只是不帶記憶。

## 刪除使用者的閘道器資料 {#delete-a-users-gateway-data}

吊銷金鑰不會刪除閘道器為使用者儲存的資料。要刪除，帳號管理員或 root 在**金鑰**標籤頁開啟該使用者任意一把金鑰的 **…** 選單，選擇**刪除該使用者的閘道器資料…**，再點**刪除閘道器資料**確認。這一操作會：

- 吊銷該使用者的全部閘道器金鑰，其客戶端立即失去訪問許可權；
- 刪除閘道器為該使用者儲存的對話狀態，包括尚未儲存到 OpenViking 的內容；
- 刪除該使用者的請求日誌。

已存入 OpenViking 的記憶不受影響。對應的 API、按帳號整體刪除以及適用場景，見[刪除資料](11-security-and-data.md#deleting-data)。
