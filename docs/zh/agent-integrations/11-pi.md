# pi Coding Agent 擴充

為 [pi](https://github.com/earendil-works/pi) 提供跨會話長期記憶和 context takeover。召回、捕獲和 takeover 基於 pi 原生擴充 API：每個 prompt 前自動召回、每個 turn 後自動捕獲，並可由 OpenViking 在 pi 的 `context` hook 中用歸檔 overview 替換已 commit 的本地歷史。擴充使用官方 MCP 客戶端，把服務端的 MCP 工具註冊成 pi 原生工具。

原始碼：[examples/pi-coding-agent-extension](https://github.com/volcengine/OpenViking/tree/main/examples/pi-coding-agent-extension)

## 工作方式

- **Session 開始**時構建 OpenViking profile 塊，並恢復 takeover 狀態，包括 `pi -c` 續跑所需的 branch 水位。profile 塊包含你的 profile、記憶索引和 `<available-skills>` 清單（你自己的和帳號共享的 OpenViking skill），每個 turn 都會附加到 pi 的系統提示詞裡；模型照某個 skill 做事之前，先用 `viking_read` 讀它的 `SKILL.md`。
- **每個 prompt** 向 OpenViking server 做語義召回，把命中的記憶作為隱藏上下文注入。
- **每個 turn** 把使用者與助手訊息（含結構化工具呼叫）捕獲進 OpenViking session；takeover 模式會在 synced token 壓力超過閾值後 commit，並在模型上下文中只保留近期 live tail。
- **Context takeover** 預設開啟。`context` hook 會先注入來自最新 archive overview 的 `[OpenViking Session Context]`，再把 recall 結果插入最新使用者訊息。
- **模型可呼叫工具**就是服務端 MCP `tools/list` 返回的工具，註冊時統一加 `openviking_` 字首——與其他記憶外掛同一套 15 個工具：`openviking_find`、`openviking_search`、`openviking_read`、`openviking_list`、`openviking_tree`、`openviking_grep`、`openviking_glob`、`openviking_remember`、`openviking_write`、`openviking_edit`、`openviking_add_resource`、`openviking_list_watches`、`openviking_cancel_watch`、`openviking_forget`、`openviking_health`。擴充自己不再維護工具清單，服務端增刪工具後，下一次 pi 會話即生效，無需釋出新版擴充。共享鍵 `mcpEnabled: false` 可關掉整個工具面，召回、捕獲和 takeover 不受影響。
- 工具握手失敗不會影響啟動。服務端不可達、憑據被拒、沒有 `/mcp` 端點時，召回、捕獲和 takeover 照常工作，只是這次會話沒有 OpenViking 工具；橋接會在後續 turn 重試，所以 pi 啟動之後才拉起的服務端不必重啟 pi 也能接上。
- 底部狀態列顯示 `OV ✓ …` 連線與捕獲狀態，握手失敗時還會追加 `tools ✗`；`/viking` 命令檢視狀態，包括已註冊的工具數量或最近一次握手錯誤，`/viking commit` 強制 commit。
- 模型用本地 `read`/`grep`/`find`/`ls`/`write`/`edit` 訪問 `viking://` URI 路徑時，呼叫會被攔截，並提示改用對應的 `openviking_*` 工具；`bash` 命令帶 `viking://` URI 時照常執行，結果末尾附一條提示，建議改用 `openviking_read` / `openviking_search`。

擴充 0.4.0 用這套映象工具面替換了原先手寫的 7 個 `viking_*` REST 工具，且不保留別名：`--tools` / `--exclude-tools` 白名單裡寫死舊名字的，必須手動改過來，否則這些工具會靜默消失。部分語義也隨之改變——`openviking_remember` 寫入獨立 session 並由服務端立即 commit，`openviking_read` 只返回全文（舊的 `level="abstract"` / `"overview"` 兩檔已移除，需要精簡檢視改用 `openviking_search(mode="context", detail="overview")` 或 `openviking_tree(include_abstract=true)`），`openviking_forget` 直接刪除給定 URI，而不是刪除某個 query 的最強匹配。Context takeover 的歸檔 overview 仍由擴充經 REST 注入，這條路徑不變。

工具呼叫和結果會作為獨立的 `tool` part 捕獲，`tool_output` 原樣上報。截斷由服務端負責：超過 `tool_output_externalization.threshold_chars`（預設 `20000`）的輸出會寫入 session 的 tool-result 儲存，part 中只保留 synopsis stub 和 `tool_output_ref`，原文仍可通過 [`/api/v1/sessions/{id}/tool-results`](../api/05-sessions.md#read-tool-result) 讀回。

## 前置條件

- Node.js 22.19.0+ 和 npm
- pi coding agent（`npm i -g @earendil-works/pi-coding-agent`）
- OpenViking HTTP server——用 `curl http://localhost:1933/health` 確認可達

## 安裝

pi 與其他記憶外掛共用同一個安裝器。它會詢問語言、要安裝的 harness、下載源和 OpenViking 憑據；每一步都是冪等的。

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/volcengine/OpenViking/main/examples/memory-plugin-shared/install.sh) --harness pi
```

在 GitHub 訪問困難的地區，可從火山引擎 TOS 映象運行同一個安裝器：

```bash
bash <(curl -fsSL https://ovrelease.tos-cn-beijing.volces.com/memory-plugin-shared/install.sh)
```

安裝器會先安裝 lockfile 中鎖定的 npm 依賴，再將擴充放到 `~/.pi/agent/extensions/openviking`，並配置 `~/.openviking/ovcli.conf`。該目錄是 pi 的自動發現根目錄之一，複製到位後 pi 會在下次啟動時自動載入，無需再執行 `pi install`。（對同一路徑再跑 `pi install` 會讓擴充被載入兩遍——一次來自自動發現，一次來自 `packages` 條目——出現重複的 `/viking` 命令。）

也可以從倉庫 checkout 手動複製：

```bash
git clone https://github.com/volcengine/OpenViking.git
cd OpenViking
node examples/memory-plugin-shared/sync.mjs
mkdir -p ~/.pi/agent/extensions/openviking
cp -R examples/pi-coding-agent-extension/. ~/.pi/agent/extensions/openviking/
npm ci --prefix ~/.pi/agent/extensions/openviking --omit=dev --ignore-scripts
```

擴充從 `shared/` 目錄 import 共享模組，這個目錄不在 git 裡，由 `sync.mjs` 生成，所以複製前必須先執行它。之後 `git pull` 更新時，也要先重新執行 `sync.mjs` 再複製。

## 配置

憑據解析順序是 `OPENVIKING_*` 環境變數、`~/.openviking/ovcli.conf`、`~/.openviking/ov.conf`——與 Claude Code、Codex、OpenCode 外掛共用。尚未配置時可執行一次嚮導：

```bash
node ~/.pi/agent/extensions/openviking/scripts/setup.mjs
```

行為與 peer 作用域旋鈕寫在 `~/.openviking/ovcli.conf` 的 `plugin` 段，與其他記憶外掛共用。`plugin.pi` 下的鍵只對本擴充生效，並覆蓋共享鍵；連線和認證憑據仍來自上面的配置源：

```json
{
  "plugin": {
    "recallPeerScope": "all",
    "scoreThreshold": 0.35,
    "recallTokenBudget": 2000,
    "profileTokenBudget": 10000,
    "skillCatalog": true,
    "skillCatalogTokenBudget": 1200,
    "resumeContextBudget": 32000,
    "commitTokenThreshold": 20000,
    "commitKeepRecentCount": 10,
    "captureAssistantTurns": true,
    "pi": {
      "workspacePeer": true,
      "peerSource": "git",
      "takeoverEnabled": true,
      "takeoverTokenThreshold": 30000,
      "takeoverKeepRecentTurns": 3,
      "takeoverOverviewBudget": 3000,
      "takeoverOverviewPollMs": 2000,
      "takeoverOverviewPollMax": 15,
      "bypassSessionPatterns": []
    }
  }
}
```

配置項按優先順序從高到低解析：`OPENVIKING_*` 環境變數、工作區的 `.openviking/config.json` 與 `config.local.json`、`plugin.pi`、`plugin`，最後是內建預設值。`autoCapture: false`（本擴充的舊拼寫是 `syncTurns`）讓它不再回寫對話，`autoRecall: false` 讓它不再檢索。

`profileTokenBudget` 只管 session 開始時注入的 profile 和記憶索引。`<available-skills>` skill 清單有獨立的預算 `skillCatalogTokenBudget`（預設 `1200`，環境變數 `OPENVIKING_SKILL_CATALOG_TOKEN_BUDGET`）：先列你自己的 skill，再列 `viking://agent/skills` 下共享的 skill；共享 skill 與你自己的 skill 同名時不再列出。放不下描述時只列 skill 名，名字也列不全時末尾註明 `... +N more`；連一個名字都放不下時，只寫一行 skill 總數。設定 `skillCatalog: false`（`OPENVIKING_SKILL_CATALOG=0`）或把預算設為 `0` 即可關閉 skill 清單；沒有 skill，或服務端沒有 `GET /api/v1/skills` 介面時，這一塊會直接省略。

`OPENVIKING_PEER_ID` 優先於所有配置檔案。在它之下，更具體的一層勝出：workspace 的 `peer.id` 和 `plugin` 段裡寫的 `peerId` 都優先於 `ovcli.conf` 的 `actor_peer_id` 和 `ov.conf` 的 `pi.peerId`。任何一層給出的顯式 peer 又都優先於 workspace 派生值。只有啟用 `workspacePeer` 且所有層都未給出 peer 時，才會從工作區派生。

`peerSource` 決定 workspace peer 的派生方式。預設的 `"git"` 取倉庫歸一化後的 `origin` URL（`git@github.com:volcengine/OpenViking.git` 得到 `github.com-volcengine-openviking`），其次是倉庫根路徑，因此同一個倉庫的每個 clone、worktree 和子目錄共用同一個 peer；不在倉庫中則完全不傳送 peer，在那裡記下的內容進入使用者級空間 `viking://user/<you>/memories`。`"cwd"` 恢復此前的行為——把工作目錄路徑中的非字母數字字元全部替換成 `-`；`"none"`（等同於 `OPENVIKING_WORKSPACE_PEER=0`）完全不傳送 peer；也可以用 `"team-{dir}"` 這樣的模板，或按順序嘗試的模板列表自定義。要讓倉庫之外的目錄擁有獨立記憶，請為它設定 `OPENVIKING_PEER_ID`（見[讓一個目錄擁有獨立記憶](../configuration/02-client.md#讓一個目錄擁有獨立記憶)）。

Takeover 是 fail-open：如果 pending 寫入無法 flush、commit 失敗、archive overview 尚未生成，或 branch 指紋不匹配，pi 會繼續保留完整本地歷史，或回退到預設 compaction。驗證邊界推進時可設定 `OPENVIKING_DEBUG_LOG=/tmp/ov-pi.log`，日誌按 JSON Lines 寫入，每個事件一行。`OV_DEBUG_LOG` 是已棄用的別名，仍然可用。

## 驗證

啟動 `pi`。連線成功後底部狀態列出現 `OV ✓` 段，`/viking` 會列印當前 session 對映和已註冊的 `openviking_*` 工具數量。問 pi 一個你在早前會話裡提到過的事情，確認召回生效。

## 故障排查

| 問題 | 排查方向 |
|------|----------|
| 狀態列顯示 `OV ✗` 或提示 "server not reachable" | `curl http://localhost:1933/health`；檢查 `~/.openviking/ovcli.conf` 中的 endpoint |
| 擴充沒有載入 | 確認 `~/.pi/agent/extensions/openviking/index.ts` 存在（該目錄會被自動發現）；重跑安裝器即可。不要用 `pi install` 註冊它——那樣會重複載入 |
| `/viking` 命令出現兩次（`viking:1` / `viking:2`） | 老版本安裝器用 `pi install` 留下了冗餘的 `packages` 條目，導致自動發現和 `packages` 各載入一次；執行 `pi remove ~/.pi/agent/extensions/openviking` 清掉該條目（只改 settings，不刪檔案） |
| 載入時報找不到 `shared/*.mjs`（例如 `shared/capture-utils.mjs`） | 手動複製前沒有執行 `sync.mjs`。在倉庫根目錄執行 `node examples/memory-plugin-shared/sync.mjs` 後重新複製，或者重跑安裝器 |
| 報錯提到 `@mariozechner/*` | pi 遷移到 `@earendil-works/*` 之前的舊副本——重跑安裝器 |
| OpenViking 返回 401 / 403 | 檢查 `OPENVIKING_API_KEY`；trusted-mode 部署還要檢查 `OPENVIKING_ACCOUNT` 和 `OPENVIKING_USER` |
| 狀態列顯示 `tools ✗`，或會話裡沒有 `openviking_*` 工具 | 用 `/viking` 檢視完整的握手錯誤。root API key 訪問 `/mcp` 會被 403 拒絕——請改用 user 或 admin key。`mcpEnabled: false` 是主動關閉工具面，不算故障 |
| recall 為空 | 確認 server 中已有記憶，且 prompt 長度超過 `minQueryLength` |

完整工具、配置與設計說明見 [擴充 README](https://github.com/volcengine/OpenViking/tree/main/examples/pi-coding-agent-extension)。
