# 用你的任務驗證效果

[第一次匯入與檢索](02-quickstart.md)跑通後，換成你工作中的資料或會話，驗證它能否幫你找到依據、複用經驗或產出內容。先選一個場景，得到結果後再擴充。

| 你希望改善什麼 | 從哪裡開始 | 看什麼結果 |
| --- | --- | --- |
| 查專案資料時少翻檔案 | [資源匯入與檢索](02-quickstart.md) | 能找到回答問題所需的原文，而不只是返回相似詞 |
| Agent 在新會話裡複用已有背景 | [選擇 Agent 接入方式](../agent-integrations/01-overview.md) | 記憶確實被儲存，並在相關任務中召回；使用者不必再次輸入相同背景 |
| 把散落資料整理成可讀的內容 | [上下文編譯](../context-compilation/01-overview.md) | 產物引用或使用了哪些來源，結構是否適合後續閱讀，是否仍有遺漏或錯誤 |

## 用自己的資料檢查檢索

選一小組你熟悉的資料，例如專案說明、操作手冊或一次問題復盤。按[快速開始](02-quickstart.md)匯入，再準備幾個你知道答案的問題。每個問題記下預期來源，檢索後讀取返回的 URI，核對原文。

至少覆蓋三種情況：資料中有直接答案；答案需要結合兩處內容；資料中沒有答案。記錄是否找到依據、是否漏掉關鍵內容，以及後續 Agent 回答是否忠於原文。`find` 返回 URI 和分數，生成回答還需要你的 Agent 或應用讀取並使用這些內容。

首次成功後，再逐步加入其他來源。這樣發現問題時，可以判斷是資料處理、檢索還是回答生成出了偏差。結果不符合預期時，使用[觀測與排障](../guides/05-observability.md)檢查處理狀態和請求行為。

## 用兩次會話檢查記憶

先檢視[整合能力對照](../agent-integrations/16-capability-reference.md)，確認你選的外掛支援哪些自動捕獲、提交和召回行為，再按該外掛的驗證步驟操作。

1. 在第一次會話中提供一條無敏感資訊、後續確實會用到的偏好或專案背景。
2. 按外掛的提交機制結束或提交會話。檢查處理狀態、實際生成的記憶及其使用者或 Peer 歸屬；提交成功不保證產生某條記憶。
3. 用同一身份開啟新會話，提出需要該背景的任務，不再次輸入那條資訊。檢查召回記錄與最終回答，確認 Agent 使用了儲存的內容。
4. 再問一個無關問題，觀察舊背景是否被不恰當地帶入回答。

外掛安裝成功不等於記憶驗證完成。若沒有產物，檢查[會話與記憶提取](../concepts/08-session.md)；已有產物卻沒有召回時，檢查身份、檢索範圍和外掛行為。應用自己管理會話時，從[應用開發路徑](../workflows/01-overview.md)進入對應 API。

## 用一份產物檢查上下文編譯

選擇[知識 Wiki](../context-compilation/02-llm-wiki.md)、[知識圖譜](../context-compilation/03-knowledge-graph.md)或[日報](../context-compilation/04-daily-report.md)中的一種，按教程準備來源並執行。先確認任務完成和產物位置，再檢查內容：

- 關鍵事實是否能回到來源核對？
- 有哪些遺漏、重複或沒有依據的表述？
- 你能否用產物完成原本的閱讀或整理任務？

第一次選你熟悉的來源，便於識別錯誤。任務成功或檔案生成，只說明處理完成；產物是否可用仍需要核對。

## 有結果後，選擇一條繼續路徑

| 當前結果 | 下一步 |
| --- | --- |
| 文件檢索滿足需要，想在日常工具裡使用 | [接入已有 Agent](../agent-integrations/01-overview.md) |
| 已驗證能力，準備寫入自己的應用 | [應用開發路徑](../workflows/01-overview.md) |
| 想使用 OpenViking 自帶的 Agent | [VikingBot 安裝與配置](../guides/17-vikingbot.md) |
| 準備讓團隊共享服務 | [選擇部署路徑](../guides/00-overview.md)，再核對身份與訪問控制 |
| 想理解結果背後的機制 | [概念與原理](../concepts/00-overview.md) |

保留試用中的問題、預期來源和實際結果，後續改配置或升級時用同一組任務複查。若要比較使用前後的變化，保持任務、模型與輸入條件一致；檢索分數和單次成功不能代替效果比較。
