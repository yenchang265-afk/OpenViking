# 效果評估

選擇你熟悉的小任務，記錄預期結果，再用相同輸入檢查實際表現。本頁提供可填寫的[評估表 CSV](/quickstart/evaluation-v1.csv)，用於首次體驗、調整配置和升級後的複查。

本輪 v1 樣例已在隔離本機服務中驗證，服務端、CLI 和 VikingBot 均為 0.5.2。模型、日期、執行範圍及遇到的問題見[樣例驗證記錄](/quickstart/verification-v1.txt)，可據此選擇與你環境相符的測試條件。

## 固定評估條件

記錄服務端、CLI、Agent 或外掛版本、模型、部署方式、身份及專案範圍。保留原始輸入和預期來源，使用獨立演示目錄。比較不同配置時，儘量保持問題、資料和模型相同；條件變化可寫入備註。

首次使用可以採用[資料檢索](08-resources.md)的四份資料，之後替換為自己的文件。每組任務記錄環境準備時間、首次有效結果時間、求助次數和跳出頁面，便於判斷入門流程是否順暢。

## 用自己的資料檢查檢索

| 用例 | 問題型別 | 核對重點 |
| --- | --- | --- |
| R1 | 單一來源有直接答案 | 回答準確，引用能開啟 |
| R2 | 需要多份來源 | 關鍵依據齊全，結論忠於原文 |
| R3 | 資料中沒有答案 | 清楚說明缺失資訊 |

依次記錄匯入任務、檢索結果、讀取 URI、最終答案及來源。若失敗，標註最早出現偏差的階段，再檢視該階段日誌。

## 用兩次會話檢查記憶

按[記憶使用](09-memory.md)先儲存一條測試約定，再用同一身份開啟新的會話。新問題只給任務，不重複約定，記錄產物、召回記錄和答案中的實際使用情況。增加一個無關問題，檢查相關性。

| 用例 | 任務 | 核對重點 |
| --- | --- | --- |
| M1 | 新會話需要原有背景 | 能使用已儲存的約定 |
| M2 | 新會話與原背景無關 | 回答保持聚焦當前問題 |

## 檢查技能與編譯產物

[技能使用](10-skills.md)採用兩組輸入，比較輸出結構、事實保留和未知資訊處理。檢查 Agent 讀取技能的記錄。[上下文編譯](13-compile.md)需要開啟至少一篇正文，逐條核對來源、遺漏和無依據表述。

版本與遷移任務可分別按[版本管理](14-versions.md)、[匯入匯出](15-transfer.md)檢查恢復範圍、檔案內容、後設資料與檢索就緒情況。

## 填寫記錄

| 欄位 | 記錄方式 |
| --- | --- |
| 問題與輸入 | 保留本次完整問題、資料版本或測試會話 |
| 預期事實與來源 | 執行前填寫已知答案及依據 URI |
| 實際答案與來源 | 儲存原始回覆和實際引用 |
| 階段與結果 | 匯入、處理、檢索、讀取、回答、儲存或召回；通過、失敗或待驗證 |
| 耗時 | 從提交到可核對結果的實際時間 |
| 環境與備註 | 版本、模型、身份、配置差異及人工修訂 |

評估表中的示例行留空，供你填寫實際結果。對主觀質量可事先約定標準，例如關鍵事實全部有依據、未覆蓋資訊明確標註、產物能支援目標任務。

## 定位問題並複查

檔案缺失先看匯入；檔案存在但查詢無結果時看索引和範圍；命中正確但回答偏差時看 Agent 讀取與生成；記憶問題按儲存、提取、召回、使用依次定位。具體診斷見[觀測與排障](../guides/05-observability.md)。

保留每次評估記錄，用同一組任務複查修訂。文件和樣例的技術驗證記錄用於說明已檢查的範圍；實際使用者能否獨立完成、能否解釋依據和替換自己的輸入，需要在稽核與試用中觀察。
