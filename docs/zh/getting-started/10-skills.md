# 技能使用

技能（Skill）將一項任務的操作方法、輸出格式和檢查要求整理成可複用的說明。對於反饋整理、報告撰寫、程式碼審查等重複任務，Agent 可以讀取技能，按照其中的要求處理不同輸入。

OpenViking 負責儲存和檢索技能，Agent 負責讀取說明並執行任務。本節以“反饋簡報”為例，帶你新增一個技能，再通過 VikingBot 處理兩組反饋，檢視同一套工作方法如何在不同會話中複用。

## 準備環境

開始前，請準備以下環境：

- **OpenViking 服務和 CLI**：按照[快速開始](02-quickstart.md)完成連線配置。
- **VikingBot**：確認服務已啟用 VikingBot，並完成模型配置。安裝與配置方法見 [VikingBot](11-vikingbot.md)。本節通過 `ov chat` 呼叫模型生成簡報，會產生相應的模型呼叫費用。
- **技能目錄許可權**：本節將技能新增到共享目錄 `viking://agent/skills/`，當前帳號需要具備寫入許可權。CLI 和 VikingBot 應連線同一服務，並使用能夠訪問該技能的帳號。

下載[反饋簡報技能包](/quickstart/feedback-brief-v1.zip)，在終端中進入下載檔案所在的目錄。包內包含 `SKILL.md` 和中英文示例輸入，可以直接用於後續操作。

## 新增樣例技能

解壓技能包，得到 `feedback-brief` 目錄：

```bash
unzip feedback-brief-v1.zip
```

將整個目錄新增到 OpenViking。`--wait` 會等待技能處理完成，便於接下來檢視內容。

```bash
ov add-skill ./feedback-brief -p viking://agent/skills --wait
```

檢視技能列表，確認其中包含 `feedback-brief`：

```bash
ov skills list
```

讀取 `SKILL.md`，瞭解 Agent 將遵循的要求：

```bash
ov read viking://agent/skills/feedback-brief/SKILL.md
```

這個技能要求 Agent 只使用當前輸入中的資訊，並按輸入語言生成以下內容：

| 內容 | 要求 |
| --- | --- |
| 已知事實 | 保留輸入中的事實和數字，標註輸入編號 |
| 建議行動 | 用表格列出行動、負責人和依據，將建議與事實區分開；負責人缺失時標為“未指定” |
| 待確認 | 列出缺失的資訊，日期缺失時標為“尚未確定” |

技能會讓 Agent 在對話中返回簡報。完成匯入後，接下來通過對話讓 Agent 讀取並使用它。如果已新增過這個樣例，可以確認技能內容後直接繼續。

## 生成反饋簡報

第一組反饋包含一個耗時資料、一項改進建議和一個待確認的日期。在新會話中提供反饋，並指定技能路徑，讓 VikingBot 按照技能要求整理：

```bash
ov chat --session feedback-skill-a -m "請先發現並讀取 viking://agent/skills/feedback-brief/SKILL.md，按技能整理以下輸入，只在對話中返回結果：反饋 A：離線匯出耗時 8 分鐘，試點管理員建議增加進度提示；上線日期未確定。"
```

簡報應包含“已知事實”“建議行動”“待確認”三部分。結合輸入核對以下內容：

- “離線匯出耗時 8 分鐘”保留在事實中，並標註輸入編號 A。
- “增加進度提示”作為建議行動呈現，負責人標為“未指定”。
- 上線日期保持為“尚未確定”，列入待確認事項。

通過工具呼叫記錄或服務日誌，還可以確認 VikingBot 是否讀取了 `SKILL.md`。這一步用於核對簡報是否基於指定技能生成。

## 換一組輸入

在另一個會話中提供第二組反饋，觀察 Agent 能否複用同樣的整理方法。使用新的會話可以避免上一組反饋影響本次結果；重複體驗時，可以將示例中的會話名換成新的名稱。

```bash
ov chat --session feedback-skill-b -m "請先發現並讀取 viking://agent/skills/feedback-brief/SKILL.md，按技能整理以下輸入，只在對話中返回結果：反饋 B：登記模板缺少問題分類欄位；有 3 條重複反饋，負責人未指定。"
```

這份簡報應保留“缺少問題分類欄位”和“3 條重複反饋”，標註輸入編號 B，並將負責人標為“未指定”。建議行動可以包括補充分類欄位、合併重複反饋，同時註明它們是基於輸入提出的建議。

對照兩份結果：內容應隨輸入變化，三部分結構、行動表和依據標註應保持一致。你也可以檢視[簡報示例與技能讀取記錄](/quickstart/skill-output-zh-v1.txt)，瞭解輸出形式。

## 檢查結果

| 檢查項 | 預期結果 |
| --- | --- |
| 技能已新增 | 技能列表中存在 `feedback-brief`，且 `SKILL.md` 可讀取 |
| Agent 已讀取技能 | 工具呼叫記錄或日誌中包含對 `SKILL.md` 的讀取 |
| 工作方法可複用 | 兩份簡報都包含約定的三部分結構、行動表和輸入編號 |
| 內容符合輸入 | 數字與事實保持準確，建議有明確標註，缺失資訊保持為待確認 |

模型生成的措辭可能有所不同，核對時以輸入事實和技能要求為準。

## 常見問題

| 現象 | 處理方法 |
| --- | --- |
| 技能未出現在列表中 | 檢視匯入命令的處理結果；如果匯入報錯，按錯誤資訊檢查服務連線、目錄許可權或模型配置 |
| CLI 能讀取技能，VikingBot 無法訪問 | 核對兩者連線的服務和帳號，並確認 VikingBot 使用的身份能夠讀取該目錄 |
| 對話中沒有技能讀取記錄 | 確認提示詞中的技能路徑可讀取，並檢查 VikingBot 的 OpenViking 工具配置 |
| 簡報結構或內容不符合要求 | 先確認 Agent 已讀取技能，再指出具體差異，請它按技能要求修訂 |

## 繼續使用

你可以把自己的工作方法整理為 `SKILL.md`，新增到 OpenViking 後供 Agent 複用。技能格式、更新方式以及其他客戶端的接入方法，見[技能參考](../api/04-skills.md)。

如果希望讓 Agent 使用技能生成可持續維護的知識庫檔案，可以繼續閱讀[上下文編譯](13-compile.md)。體驗結束後，如需清理樣例，可在 Studio 中確認 `feedback-brief` 是本次新增的技能後刪除。
