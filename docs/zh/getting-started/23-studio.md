# Studio 入門

OpenViking Studio 是服務自帶的 Web 介面。你可以在瀏覽器中檢視已匯入的資料、檢索相關內容、瀏覽記憶和技能，並跟蹤後臺任務的處理情況。通過 Studio，可以把命令列返回的 `viking://` URI 與實際內容對應起來，核對 Agent 使用的上下文。

本節從連線服務開始，帶你瀏覽首頁、開啟資料原文、執行一次檢索，再檢視任務狀態。完成後，你可以在頁面中確認資料是否可讀、能否被檢索到，以及處理任務是否完成。

## 準備服務

準備一個正在執行的 OpenViking 服務，以及對應的訪問地址。首次使用時，可按[快速開始](02-quickstart.md)完成安裝、模型配置和啟動；已完成初始化但尚未啟動本地服務時，在終端執行：

```bash
openviking-server
```

保持終端執行，在瀏覽器中開啟 [Studio](http://127.0.0.1:1933/studio/)。預設本地埠為 `1933`；使用其他埠或遠端服務時，將地址替換為實際服務地址，並在末尾加上 `/studio/`。

啟用 API Key 認證的服務需要準備 User Key；具有管理職責的使用者也可以使用 Admin Key。金鑰由管理員建立，操作方法見[認證](17-authentication.md)。本地開發模式未啟用認證時，金鑰可以留空。

下方截圖使用埠為 `1940` 的獨立本地演示服務，包含虛構的燈塔專案資料。首次啟動的服務可能尚無資料，可以先完成快速開始中的資料匯入，再跟隨本文瀏覽。

## 連線服務

首次開啟 Studio 時，在連線嚮導中選擇服務型別。本地部署選擇**開源服務**，填寫服務地址，例如 `http://127.0.0.1:1933`，然後選擇介面語言並進入下一步。

![連線嚮導：選擇開源服務並填寫本地服務地址](/quickstart/studio/connect-zh.jpg)

在身份頁面填寫使用者 API Key，點選**驗證連線**。驗證成功後，核對頁面顯示的 Account 和 User，再點選**進入 Studio**。後續瀏覽和檢索使用這個身份對應的資料範圍。

![驗證連線：顯示當前 Account 和 User](/quickstart/studio/identity-zh.jpg)

Root/Admin Key 是可選的管理憑據，按需要配置；日常資料訪問使用使用者身份。身份和許可權的詳細說明見[認證](17-authentication.md)。已有連線時，可通過左上角的連線名稱切換，也可以在**連線設定**中調整連線資訊。

## 檢視首頁

首頁展示上下文資料量、今日 Token 用量、今日檢索次數，以及用量和提交趨勢。匯入資料或執行檢索後，可以回到這裡瞭解使用情況；剛啟動且尚未使用的服務，部分統計可能為空或為零。

![首頁：上下文資料量、Token 用量和檢索次數](/quickstart/studio/home-zh.jpg)

左側導航分為工作區、活動和設定。日常檢視內容從**檔案系統**和**檢索**開始，處理進度在**任務中心**檢視，服務狀態在**監控**中檢視。

## 瀏覽資料

開啟**檔案系統**，展開 `resources`，找到已匯入的資料目錄，再點選檔名。中間區域顯示檔案內容；Markdown 檔案可以切換**預覽**和**原始碼**，頂部可以複製完整的 `viking://` URI，供後續檢索或交給 Agent 引用。

![檔案系統：展開燈塔專案目錄並閱讀資料原文](/quickstart/studio/files-zh.jpg)

以燈塔專案為例，開啟原文後可以確認：反饋儲存到本地檔案，每週由試點管理員匯出並交給專案負責人，第一版不提供雲端同步。核對這些具體事實，能夠幫助你判斷 Agent 的回答是否忠於資料。

檔案系統也提供其他上下文的入口：`user` 用於檢視使用者記憶，`agent` 用於檢視 Agent 的技能和經驗。頁面中可見的目錄和可執行操作取決於當前身份及授權範圍。

需要匯入新資料時，點選介面中的**新增資源**，按表單選擇來源和目標位置。匯入後先到任務中心確認處理結果，再開啟檔案核對內容。目錄和匯入方式見[資料檢索](08-resources.md)；頂部的歷史版本和 OVPack 入口分別對應[版本管理](14-versions.md)與[匯入匯出](15-transfer.md)。

## 檢索內容

開啟**檢索**，選擇 `find`，輸入一個具體問題，例如“燈塔專案第一版應怎樣收集使用者反饋，需要提前準備什麼？”。在檢索範圍中選擇**自定義 URI**，填寫剛才資料所在目錄的 URI，然後點選檢索按鈕或按 Enter。

如果沿用快速開始的目錄，填寫 `viking://resources/lighthouse-demo`。截圖中的演示目錄是 `viking://resources/lighthouse-demo-zh`，實際操作時以檔案系統中複製的 URI 為準。

![檢索：限定燈塔專案目錄，返回原文和目錄摘要](/quickstart/studio/retrieval-zh.jpg)

結果展示 URI、內容描述、上下文層級和相關度。點選檔案結果可以檢視內容；如果命中的是目錄摘要，可以繼續進入對應目錄閱讀原文。相關度用於比較檢索結果與問題的匹配程度，回答中的事實仍需結合原文核對。

頁面中的幾種檢索方式適用於不同目的：

| 方式 | 適用場景 |
| --- | --- |
| `find` | 按語義查詢與單次問題相關的上下文 |
| `search` | 使用增強檢索，結合會話等上下文理解查詢意圖 |
| `grep` | 在檔案內容中匹配文本或正規表示式 |
| `glob` | 按路徑模式查詢檔案 |

需要讓 Agent 綜合資料生成回答時，可繼續使用 [VikingBot](11-vikingbot.md) 或[接入自己的 Agent](../agent-integrations/01-overview.md)。

## 跟蹤任務

資料匯入、會話提交和索引重建等操作會產生後臺任務。開啟**任務中心**，按任務型別或狀態篩選，再點選對應任務，檢視關聯 URI、工序進度、耗時和執行日誌。

![任務詳情：資料處理完成，並顯示解析、語義處理和嵌入向量進度](/quickstart/studio/task-zh.jpg)

任務顯示**已完成**後，回到檔案系統和檢索頁面檢查產物。任務出現異常時，先檢視詳情中的錯誤和執行日誌，確認問題發生在哪個環節，再按提示檢查配置或輸入內容。

**會話**頁面用於瀏覽對話記錄，並檢視會話提交帶來的記憶變化。要體驗從對話中提取記憶、在後續任務中召回的完整流程，可以繼續閱讀[記憶使用](09-memory.md)。

## 使用其他頁面

| 頁面 | 可以完成的工作 | 後續閱讀 |
| --- | --- | --- |
| VikingBot | 與內建 Agent 對話，結合資料完成任務；需要服務啟用 Bot | [VikingBot](11-vikingbot.md) |
| 技能 | 瀏覽和管理技能，檢視可供 Agent 使用的操作說明 | [技能使用](10-skills.md) |
| 編譯 | 將源資料整理為 Wiki 等可複用內容；需要可用的 Compile Runtime | [上下文編譯](13-compile.md) |
| Agent 經驗 | 檢視 Agent 積累的經驗上下文 | [記憶使用](09-memory.md) |
| 請求日誌 | 檢視請求記錄，輔助排查呼叫問題 | [可觀測性與排障](../guides/05-observability.md) |
| 定時同步 | 檢視和管理已配置的資料同步任務 | [定時同步 API](../api/15-watches.md) |
| 監控 | 檢視服務健康狀態及佇列、模型、儲存等元件狀態 | [可觀測性與排障](../guides/05-observability.md) |
| OpenViking 閘道器 | 管理模型上游、上下文策略和閘道器接入憑據 | [閘道器接入](12-gateway.md) |

頁面中可用的能力隨服務配置和當前許可權變化。需要為團隊劃分資料範圍或授權共享時，從 [Account](18-accounts.md) 和[訪問控制](21-access-control.md)瞭解配置方法。

完成瀏覽後，建議用自己的一個問題執行檢索，開啟結果原文，再與 Agent 的回答逐條對照。可以按[效果評估](06-evaluate.md)記錄結果，判斷資料覆蓋和回答質量是否滿足任務需要。
