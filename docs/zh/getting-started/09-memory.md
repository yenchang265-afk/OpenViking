# 記憶使用

記憶讓 Agent 在新的會話中繼續使用已經瞭解的偏好、專案背景和工作經驗，減少重複說明。OpenViking 可以在會話提交後提取值得保留的資訊，供 Agent 在後續任務中檢索和使用。

下面以虛構的海岬專案為例：先儲存評審習慣，再開啟一個新會話，讓 VikingBot 根據這些記憶準備評審提綱。完成後，你可以檢視記憶正文、核對召回來源，並確認回答是否沿用了專案約定。

## 適用場景

| 場景 | 可以保留的資訊 | 後續如何使用 |
| --- | --- | --- |
| 個性化回答 | 常用語言、摘要格式、表達偏好 | 按使用者熟悉的方式組織回答 |
| 專案協作 | 專案背景、已有決定、檔案命名約定 | 開啟新會話後繼續處理專案任務 |
| 經驗複用 | 解決問題時有效的方法和注意事項 | 遇到類似問題時檢索已有經驗 |

記憶會根據輸入內容和服務端配置提取、整理。同一段對話可能產生多條記憶，也可能更新已有記憶；具體分類見[記憶型別](../api/16-memory.md#內建記憶型別)。

<a id="準備獨立實驗"></a>

## 準備環境

先按[快速開始](02-quickstart.md)連線服務，完成 [VikingBot](11-vikingbot.md) 的啟用與連線配置。服務端需要可用的記憶提取和 Embedding 模型，VikingBot 需要能夠呼叫 OpenViking 檢索工具。

本流程通過 CLI 儲存會話，再由 VikingBot 召回。兩者應連線同一服務、使用同一使用者身份，讓新會話能夠訪問前面儲存的記憶。本例使用使用者自身的記憶空間，專案外掛的身份與 Peer 範圍可參考[整合能力對照](../agent-integrations/16-capability-reference.md)。

以下操作會呼叫模型，並將虛構專案的資訊寫入當前使用者的記憶。可使用專門的演示帳號體驗，便於之後清理。會話名稱使用下方示例值即可；若已經使用過這些名稱，請更換名稱並同步修改後續命令。

<a id="會話-a-儲存約定"></a>

## 儲存專案背景

先建立一個會話，用於記錄海岬專案的評審約定。`--no-auto-commit` 將提交時機交給後面的手動操作：

```bash
ov session new --session-id cape-docs-a --no-auto-commit
```

向這個會話寫入一條使用者訊息，說明希望在後續評審中複用的背景：

```bash
ov session add-message cape-docs-a --role user --content "這是虛構的海岬專案。我們每次評審只討論兩項風險，摘要使用中文三條要點，交付檔案統一命名為 cape-review.csv。以後準備海岬評審時請遵循這些約定。"
```

提交會話，讓服務歸檔訊息並開始提取記憶：

```bash
ov session commit cape-docs-a
```

記錄返回的 `task_id` 和 `archive_uri`。`accepted` 表示訊息已歸檔、記憶提取已進入後臺處理；接下來查詢任務，確認記憶是否生成。

## 檢視生成的記憶

將 `<task_id>` 替換為提交時返回的任務 ID：

```bash
ov task status <task_id>
```

狀態為 `completed` 後讀取結果。可以每隔 5 秒檢查一次，先觀察最多 2 分鐘；仍在執行時保留任務 ID，稍後繼續。若狀態為 `failed` 或 `cancelled`，先檢視任務錯誤或取消原因，再決定後續操作。

將 `<archive_uri>` 替換為提交時返回的歸檔 URI，讀取本次記憶變更：

```bash
ov read "<archive_uri>/memory_diff.json"
```

在 `operations.adds` 或 `operations.updates` 中找到 `uri`，複製該值讀取記憶正文：

```bash
ov read "<記憶 URI>"
```

核對正文是否保留了三個要點：每次評審討論兩項風險、摘要使用三條中文要點、交付檔名為 `cape-review.csv`。記憶的檔名和分類可能不同，以實際返回的 URI 為準。

<a id="會話-b-使用背景"></a>

## 在新會話中使用

使用新的 VikingBot 會話 ID，只提供專案名稱和新任務。具體的風險數量、摘要格式和檔名由 Agent 從已儲存的記憶中獲取：

```bash
ov chat --session cape-docs-b -m "請檢索已儲存的海岬專案記憶，按專案約定準備下一次評審提綱，並說明建議的交付檔名。請引用使用的記憶 URI。"
```

核對回答是否包含兩項風險的討論位置、三條中文摘要要點，以及檔名 `cape-review.csv`。本次輸入沒有提供具體風險，提綱可將風險內容標為待補充。

結合工具呼叫輸出或 Bot 日誌，檢查儲存、召回和使用三個環節：

| 環節 | 核對內容 |
| --- | --- |
| 儲存 | `memory_diff.json` 記錄了變更，記憶正文包含專案約定 |
| 召回 | 檢索工具結果包含對應的記憶 URI 和內容 |
| 使用 | 新回答遵循約定，引用的記憶 URI 與檢索結果一致 |

再開啟一個新會話，檢視回答是否能保持與當前任務相關：

```bash
ov chat --session cape-docs-c -m "17 加 25 等於多少？"
```

這個問題的答案應為 42，回答無需加入海岬專案的評審格式或檔名。

<a id="定位問題"></a>

## 常見問題

| 遇到的情況 | 檢查方式 |
| --- | --- |
| 提交返回 `skipped` | 本次沒有可歸檔訊息；用 `ov session get cape-docs-a` 檢查訊息是否已新增或已提交 |
| 任務失敗或一直未完成 | 檢視任務狀態和錯誤資訊，檢查模型連線及服務端記憶配置 |
| 沒有生成預期記憶 | 核對原訊息、`memory_diff.json` 和生效的提取策略；相同資訊也可能已儲存在已有記憶中 |
| 已儲存但新會話沒有召回 | 檢查 CLI 與 VikingBot 的服務地址、使用者身份、記憶範圍和檢索工具是否可用 |
| 已召回但回答沒有使用 | 檢視工具返回內容和 Agent 指令，讓 Agent 依據召回的記憶修訂回答 |

## 繼續使用

換成自己的專案背景或回答偏好後，可以用[效果評估](06-evaluate.md)記錄相關任務和無關任務的表現。接入已有 Agent 時，各外掛的會話捕獲、提交與召回方式見[整合能力對照](../agent-integrations/16-capability-reference.md)；會話引數和變更記錄格式見[會話 API](../api/05-sessions.md)。

體驗結束後，可在 Studio 中根據本次 `memory_diff.json` 確認演示記憶，再按需清理會話和記憶。若本次更新了已有記憶，先核對修改內容，保留仍需使用的資訊。
